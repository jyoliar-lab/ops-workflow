# 템플릿 — frontmatter · 구조의 예 · 적지 않는 것

SKILL.md §4·§5의 상세다. 쓰기 직전에 읽는다.

## frontmatter

```yaml
---
type: digest
goal: <같은 목표의 discussion과 같은 값>
topic: <폴더와 일치>
subjects: [<구체 명사만 — 시스템에 실재하는 것>]
status: current             # → superseded
ref-adrs: [<이 설계가 기대거나 낳을 ADR id>]
sources: [<덮은 discussion 경로 — 전부>]
superseded_by:              # 교체될 때 새 digest 경로
---
```

## 몸통

```markdown
# <제목 — 무엇의 설계인가> (YYYY-MM-DD 시점)

## 개요
<한 단락. 이 설계가 무엇을 위한 무엇인가. 처음 열었을 때 이 단락으로 대상이 잡힌다>

<이하 구조는 대상이 정한다 — 아래 "구조의 예">
```

한 줄에 한 문장(`.claude/rules/readability.md`).

## 구조의 예

대상이 다르면 구조가 다르다. 셋 다 사례 하나가 처음부터 끝까지 관통한다.

**프로세스·하네스** — 사용 장면의 연쇄.

```markdown
## 어휘
<이 설계가 쓰는 말 — 짧게>

## 1. <첫 장면 — 사람이 무엇을 하면>
<무엇이 일어나는가. 사례로>

## 2. <다음 장면>
…

## N. 그 뒤
<이 설계의 산출물이 어디로 가는가>

## 이 체계가 하지 않는 것
<선택. 독자가 없는 기능을 찾지 않게>
```

**시스템·인프라** — 구성과 흐름.

```markdown
## 구성
<무엇이 어디에 있나 — 사례의 실제 이름으로>

## 데이터 흐름
<사례의 데이터 하나가 들어와서 나가기까지>

## 장애 시 동작
<구성 요소 하나가 죽으면>

## 운영
<백업·갱신·확장이 어떻게 일어나나>
```

**컴포넌트·모듈** — 입력·동작·출력.

```markdown
## 입력
## 동작
## 출력
## 경계 — 이 컴포넌트가 하지 않는 것
```

## 사례가 관통한다는 것

사례는 설계를 설명하는 장치이지 장식이 아니다.
첫 절에서 사례를 소개하고(홈랩에 HDD 스토리지를 들인다 · 사진 라이브러리 하나가 저장된다), 그 뒤 모든 절이 그 사례의 다음 장면을 보인다.
한 절에서 사례가 끊기면 그 절의 설계가 전체와 어떻게 이어지는지 독자가 잃는다.

## 적지 않는 것

| 들어오면 | 왜 아닌가 | 그것이 사는 곳 |
|---|---|---|
| "X를 택한 이유는", "Y는 버렸다" | 설계가 아니라 결정의 요약이다 | discussion의 선택·판정 줄과 버린 안 |
| "처음 A였다가 B로" | 경위다 | discussion |
| 옵션 비교표 | 결정 전의 지형이다 | discussion 열린 축 |
| "ADR-00NN에 따라", "티켓 #NNN에서" | 결정별 행선지 추적이다 | frontmatter `ref-adrs` |
| "미결", "아직 정해지지 않음" | 열린 것이 있으면 수렴이 아니다 | discussion(`active`) |
| "사람에게 묻는다" | 질문은 채팅에서 | 채팅 |
| "자세한 것은 `…/discussion/…`" | 자족하지 않는다 | frontmatter `sources` |
