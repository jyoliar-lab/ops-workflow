# 인터뷰 — 질문의 모양, 이해 못 함, 닫힌 축과 열린 축

SKILL.md §2·§3의 상세다. 인터뷰를 시작하기 전에 한 번 읽는다.

## 고정 축 — 질문의 모양

축의 순서와 뜻은 SKILL.md §2의 표다. 여기는 **어떻게 묻나**다.

선택지는 **구체적으로** 쓴다. "읽기 어렵다"가 아니라 "며칠 뒤 다시 열었을 때 무엇이 닫혔고 무엇이 열려 있는지 처음부터 읽어야 안다". 추상적인 선택지는 사람이 자기 상황에 대입하지 못한다.

| 축 | 예 |
|---|---|
| ① 증상 | "장애를 알아채는 순간은 언제입니까?" — 알럿이 올 때 / 사용자가 제보할 때 / 대시보드를 열어 봤을 때 / 다음 날 로그에서 |
| ② 비용 | "그때 무엇을 다시 합니까?" — 재배포 / 수동 복구 / 원인 추적에 반나절 / 잘못 내린 결정을 되돌림 |
| ③ 산출물 | "끝났을 때 무엇이 있어야 합니까?" — 설정 변경 하나 / 새 컴포넌트 / 결정 기록만 / 티켓 트리 |
| ④ 제약 | "바꿀 수 없는 것은?" — 예산 · 이미 accept된 결정 · 기한 · 쓰고 있는 제품 |
| ⑤ 범위 | "이번에 다루지 않을 것은?" — 인접 시스템 / 마이그레이션 / 비용 최적화 |

## 후속 질문 — 답이 낳는 의문

답 하나가 다음 질문을 가른다. 처음에 많이 묻는 이유는 문서가 생긴 뒤의 수정이 누적의 시작이기 때문이다 — 인터뷰에서 10분 더 쓰는 것이 문서에서 10번 고치는 것보다 싸다.

- **답이 다른 축의 전제를 바꾸면** 그 축을 다시 묻는다.
- **답이 선택지 밖이면**(기타) 그것이 가장 값진 답이다 — 선택지가 틀렸다는 뜻이다. 그 답을 중심으로 다시 묻는다.
- **답이 전제를 뒤집으면** 멈추고 뒤집힌 것을 말한다. 다음 질문을 이어가지 않고 틀을 다시 세운다.
- **한 번에 넷까지.** 서로 독립인 질문은 한 번에, 의존하는 질문은 다음 라운드로.

## 사람이 질문을 이해하지 못했을 때

사람은 "기타"에 이해하지 못한 부분을 적어 온다 — "하네스 파일이 무엇입니까?"처럼.
그러면 **인터뷰를 일시 중단한다.** 그 부분을 명확히 설명하고, 사람이 재개를 지시할 때까지 다음 질문을 하지 않는다.
설명 뒤에 같은 질문을 다시 할 때는 설명에 맞춰 선택지를 고쳐 쓴다 — 설명 과정에서 질문의 전제가 틀렸음이 드러나는 일이 흔하다.

모든 질문에 "왜 묻는가"를 붙이거나 예시를 다는 것은 하지 않는다. 질문이 길어지고, 이해 못 함은 어차피 사람이 되묻는 것으로 처리된다.

## 종료

더 물을 것이 없으면 **선언하고 확인을 받는다** — "더 물을 것이 없습니다. 쓰겠습니다." 사람이 확인하면 쓰고, 더 있다고 하면 이어간다.
사람은 언제든 "이제 쓰자"로 끊을 수 있다. 그것은 실패가 아니라 사람이 끝을 정한 것이다.

## 닫힌 축과 열린 축

축마다 묻는다 — **이 답은 사람이 이미 가진 것에서 나오는가, 새로 만들어야 하는가.**

| | 닫힌 축 | 열린 축 |
|---|---|---|
| 답의 출처 | 사람의 의도·취향·제약·범위 | 사람이 갖지 않은 사실 |
| 새 사실 | 필요 없다 | 실측(코드)·조사(외부)가 필요하다 |
| 되돌리기 | 쉽다 — 하네스·규약 | 어려울 수 있다 — one-way door |
| 옵션 공간 | 작고 사람이 이미 안다 | 비교표를 봐야 고를 수 있다 |
| 전형 | 작업 방식·선호·범위 | 코드 제약 · 선행 사례 · 서로 묶인 축 · 해법의 모양을 한 요구 |

**예 — 닫힌 축.** "질문–답 왕복은 어디에 남기길 원합니까?" → "채팅에서만". 사람의 선호이고 실측이 답을 바꾸지 않는다. 인터뷰에서 닫힌다.

**예 — 열린 축.** "SEO를 위해 SSR을 넣자"는 요구로 왔지만, SEO 목표가 무엇인지(어떤 검색어로 들어오길 원하나)는 조사 전엔 모르고, 렌더링 전략은 프레임워크 선택에 묶여 있었다. 옵션을 펼쳐야 고를 수 있다.

**예 — 즉석 답이 왔지만 열린 축.** "GA를 위해 SSR"이라는 답은 즉석에서 나왔지만 사실(해시 라우팅 제거만으로 GA가 되는가)에 기댄다. 받되 "이 축은 X를 실측해야 닫힌다"고 말하고 열린 축으로 둔다. 틀린 즉석 답이 닫힌 축으로 들어가면 문서가 생긴 뒤에 뒤집히고, 그것이 누적의 시작이다.

어느 쪽이 많은가는 주제가 정한다. 작업 방식을 정하는 논의는 거의 닫힌 축이고, 코드·외부 제품이 얽힌 논의는 반대다. 둘 다 정상이다 — 열린 축이 없으면 §4에 "없음"과 이유 한 줄을 적는다.
