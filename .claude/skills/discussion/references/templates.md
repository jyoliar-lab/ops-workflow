## frontmatter

```yaml
---
type: discussion
kind: deliberation          # 또는 survey
goal: <kebab-slug>          # 같은 목표의 논의·digest가 공유. 첫 관점이면 지금 짓는다
topic: <폴더와 일치>
subjects: [<구체 명사만 — 시스템에 실재하는 것>]
status: active              # → done / rejected
ref-adrs: []                # 이 논의가 다루거나 낳은 ADR id
related: []                 # 조사 문서 · 같은 목표의 앞선 논의 (경로)
---
```

`kind`·`goal`·`related`는 ADR-0022가 열어 둔 자유 필드다 — 정책 변경 없이 쓴다. 필요하면 더 더한다.

<코드·코퍼스에서 읽은 사실. 불릿. 조사 문서가 있으면 related로 가리키고 여기엔 결론에 쓰인 것만>

## 닫힌 축 · 열린 축의 모양

**닫힌 축** — 선택 줄만 읽어도 결정이 보여야 한다. 버린 안은 GitHub에서 접히고 에디터에서는 아래 붙는다.

```markdown
### 3-5. 외부 조사의 자리

**선택: 별도 discussion(조사 문서)으로 분리한다.** 조사 전문은 사고의 재료라 보관 지위가 같아야 한다. (인터뷰, 2026-10-06)

<details><summary>버린 안</summary>

- discussion 안 전용 절 — 조사 전문이 사라진다
- 임시 파일에 전문 — 보관 지위가 discussion과 달라진다

</details>
```

선택이 바뀌면 선택 줄을 고쳐 쓰고 옛 선택을 버린 안으로 내린다. 경위를 한 구절 남겨도 된다 — "(처음 A였다가 바꿨다. 이유 한 줄)". 문단이 되면 안 된다.

**열린 축** — 옵션 전체가 본문이다. 접지 않는다. 판정은 한 줄.

```markdown
### 4-2. 렌더링 전략

실측: 현재 해시 라우팅이라 모든 경로가 한 HTML이다. GA 집계는 해시 제거만으로 된다.

- **A. 공개 라우트만 SSR** — SEO 목표가 "집계·리뷰 결합 검색어"일 때 이긴다 / 목표가 없으면 비용만 든다
- B. 전부 SSR — 토큰 저장 축(D)까지 끌려 들어온다
- C. 안 한다(CSR 유지 + 해시 제거) — GA만이 목표면 충분하다

**판정(사람, 2026-07-17): C. SEO 목표는 별도 조사 Task로 뗀다.**
```

## 조사 문서 템플릿

외부 조사는 논의 문서에 넣지 않고 따로 쓴다 — 조사 전문은 사고의 재료라 보관 지위가 discussion과 같아야 하고, 논의 문서에 넣으면 논의가 조사에 묻힌다.

```yaml
---
type: discussion
kind: survey
goal: <논의 문서와 같은 값>
topic: …
subjects: […]
status: active              # 조사가 끝나면 done
related: [<이 조사를 요구한 논의 문서>]
---
```

```markdown
# <무엇을 조사했나> — 조사 (YYYY-MM-DD)

## 질문
<논의 문서의 어느 축이 무엇을 알고자 했나 — 한 단락>

## 조사
<자유 형식. 조사한 내용을 그 내용에 맞는 구조로 서술한다 — 비교표, 사례별 절, 시간순, 산문, 무엇이든.
 형식은 자유이되 출처는 자유가 아니다: 주장마다 출처(URL·문서명)와 핵심 인용, 조사일을 그 자리에 단다>

### <소제목 — 조사 내용이 요구하는 구조대로>
…

## 논의 문서로 가져가는 것
<결론에 쓰일 사실만 추려 한 줄씩. 논의 문서 §2 실측이 이것을 가리킨다>
```

조사 절이 자유 형식인 이유 — 선행 사례 비교, 제품 조사, 표준 문서 독해는 각각 다른 모양을 요구한다. 불릿 하나에 사실 하나로 눌러 넣으면 사례 사이의 관계와 맥락이 사라진다.
자유가 아닌 것은 **출처**다 — 출처 없는 주장은 적지 않는다. 조사 문서에는 **판정이 없다** — 조사는 결정하지 않는다. 산만해지면 조사 범위가 문제를 겨냥하지 않은 것이다 — 인터뷰로 돌아간다.

## 누적의 표식 — 금지

이것이 보이면 로그가 아니라 누적이다.

| 금지 | 대신 |
|---|---|
| "사람에게 묻는다" · "열린 질문 — 사람의 것" 같은 **질문 절** | 채팅에서 묻는다. 문서엔 합의된 문제(§1)만 |
| "답 — 2026-09-30" · "N라운드" · "추기" 같은 **덧붙임 절** | 선택·판정 줄을 그 자리에서 고쳐 쓴다 |
| **문단이 된 판정** — 경위·재논의가 판정 아래 이어지는 것 | 판정은 한 줄. 경위는 한 구절까지 |
| **대화의 속기록** | 옵션·축·버린 이유만 |
| 판정이 난 축에 **옵션 추가** | 판정을 되돌리는 것이다 — 사람이 채팅으로 말한다 |
