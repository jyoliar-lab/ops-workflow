# ADR-0029 — 토큰의 신뢰는 데이터 경로의 로컬 검증으로만 얻는다

## Context

인증을 외부 IdP 제품에 위임하면(ADR-0028) auth-service와 api-composer 둘 다 제품이 발급한 토큰의 검증자가 된다. 검증자가 토큰을 신뢰하는 방법은 크게 둘이다 — **로컬 검증**(비대칭 서명을 공개키로 자기 프로세스 안에서 확인)과 **원격 확인**(요청마다 발급자에게 유효성을 묻는 introspection, 또는 게이트웨이에 검증을 집중).

원격 확인은 폐기 즉시 발효라는 장점이 있지만, 지금 존재하지 않는 런타임 결합을 **모든 요청의 경로 위에** 신설한다. api-composer는 현재 다른 서비스를 호출하지 않고 자기 안에서 검증을 끝내며, 그래서 인증 계통의 장애가 조회 경로의 장애로 번지지 않는다. 이 성질은 우연이 아니라 지킬 가치가 있는 경계다 — 한 번 "즉시 발효가 필요하지 않나"라는 합리적인 요구에 밀려 원격 확인을 들이면, 발급자가 전 요청의 단일 장애점이 되고 되돌리는 것은 서비스 경계를 다시 바꾸는 일이 된다.

한편 로컬 검증에도 발급자와의 접점은 있다 — 공개키를 어디선가 받아야 한다. 이 접점을 요청 경로의 결합과 같은 것으로 취급하면 판단이 흐려지므로, 결합의 **종류**를 결정의 어휘로 가른다.

검증 코드가 여러 서비스에 존재하는 것 자체는, 비대칭 서명 아래에서는 위험이 아니다 — 공개키 사본은 발급 능력을 주지 않는다. 과거 대칭키 체계에서 사본 확산이 위험했던 이유(검증자가 곧 발급자)가 소멸한다.

## Decision

**제품 토큰의 신뢰는 데이터 경로의 로컬 검증으로만 얻는다.**

- **요청 처리 경로에 검증 목적의 원격 호출을 두지 않는다.** introspection을 쓰지 않고, 게이트웨이에 검증을 위임하지 않으며, 다른 서비스를 경유해 검증하지 않는다. 각 서비스가 공개키로 서명·`iss`·`aud`·`exp`를 자기 안에서 확인한다.
- **결합의 종류를 가른다 — 데이터 경로와 제어 경로.** 요청마다 발생하는 원격 호출(데이터 경로)은 금지 대상이고, 키 획득(JWKS 조회)은 **캐시되는 제어 경로**로 허용한다. 캐시된 키로 검증은 발급자 장애 중에도 계속 동작한다.
- **폐기·정지·권한 변경의 발효는 액세스 토큰 수명만큼의 지연을 수용한다.** 지연의 크기(토큰 수명)는 설정의 관할이다.

## Alternatives

- **introspection (요청마다 원격 확인).** 즉시 발효를 얻는 대신 발급자가 전 요청 경로의 단일 장애점이 된다. 위험한 조작이 특정 서비스(auth-service)에 몰려 있는 구조에서, 전 경로가 그 비용을 낼 이유가 없다.
- **게이트웨이 집중 검증(엣지 인증).** 검증을 네트워크 경계 한 곳으로 모으고 뒤의 서비스는 신뢰된 신원 전달을 받는 실무 패턴이다. 파는 가치는 검증 코드의 단일화인데, 검증자가 둘(auth-service·api-composer)뿐이고 같은 언어라 공용 모듈로 같은 것을 얻는다 — 이득이 ~0이다. 반면 현행 게이트웨이에는 JWT 검증 기능이 없어 지원 게이트웨이의 조사·도입이 선행 비용이 되고, 내부 홉에서 검증이 소멸하는 구조는 홉마다 검증하는 제로트러스트 흐름에 역행한다.
## Consequences

- **회수의 지연을 산다.** 탈퇴·정지된 사용자의 액세스 토큰이 수명까지 유효하다. 발급자 측에서 갱신(refresh)은 즉시 끊기므로 노출 창의 상한은 액세스 토큰 수명이다.
- **위험 조작에 즉시 차단이 필요해지면, 이 결정과 양립하는 강화 경로가 있다.** 발급자의 이벤트를 push로 받아(제품의 이벤트 훅) 로컬 차단 플래그를 두면, 요청 경로는 여전히 로컬 조회만 하면서 준즉시 발효를 얻는다 — 주기 조정이 전달 실패의 백스톱이 된다. 도입 여부는 별도 판단으로 미룬다.
- **제어 경로의 실패 모드를 코드가 다뤄야 한다.** 발급자 다운 중의 프로세스 콜드 스타트(첫 키 조회 실패)와 키 회전 추종은 재시도·캐시 지속화 등으로 완화한다 — 방식은 코드 관할이다.
- **검증 로직이 서비스마다 존재한다.** 공통 모듈로 관리해 드리프트를 막는다. 비대칭이므로 공통화가 발급 능력을 확산시키지 않는다.

## 무효화 조건

- **전 경로에서 폐기의 즉시 발효가 요구 사항이 되는 경우.** 지연 수용이 이 결정의 기둥이다 — 그 전제가 깨지면 원격 확인 계열을 다시 벌여야 한다.
