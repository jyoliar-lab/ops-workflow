# ADR-0031 — 인가 전파는 발급 시점 클레임 주입으로 한다

## Context

인증은 외부 IdP 제품이 소유하고 인가의 원장(권한·동의)은 앱(auth-service)이 소유하도록 경계를 갈랐다.
경계가 서면 접합 문제가 남는다: 토큰은 제품이 발급하는데 인가의 진실은 앱 DB에 있고, 각 서비스(api-composer·auth-service)는 요청마다 인가를 판정해야 한다. 진실의 위치와 판정의 지점을 어떻게 잇는가가 이 결정이다.

전제 둘이 선택지를 가른다.

**인가 상태의 모양** — careerhub의 인가는 사용자만의 함수다. 권한은 평평한 목록(만료 포함)이고 동의는 충족 플래그다. 리소스 단위 권한·계층·공유·멀티테넌시가 없다. 그래서 한 사용자의 인가 상태 전체가 토큰에 실릴 만큼 작고, 변경(권한 부여·동의 완료·회수)은 요청 빈도에 비해 드물다.

**수단의 실재** — 현행 IdP 제품은 토큰 발급 시 등록된 외부 endpoint를 호출해 그 응답을 클레임으로 싣는 훅을 1급 기능으로 제공한다. 인가 데이터를 앱이 소유한 채로 토큰에 실을 경로가 실재한다.

## Decision

**제품이 토큰을 발급할 때 앱을 호출해 인가 상태를 클레임으로 주입하고, 각 서비스는 클레임만으로 인가를 판정한다.**

- **발급 시점 주입** — 제품의 발급 훅이 앱(auth-service)을 호출해 권한·동의 충족 상태를 받아 토큰 클레임으로 싣는다.
- **요청 경로에는 인가 목적의 조회를 두지 않는다** — 서비스가 요청을 처리하며 인가 저장소나 타 서비스에 묻지 않는다. 판정의 입력은 클레임뿐이다.

클레임의 이름·모양과 판정 코드는 코드의 관할이다.

## Alternatives

**체크타임 조회.** 서비스가 요청마다 권한 저장소를 조회한다. 인가 변경의 즉시 발효를 얻는 대신, 지금 존재하지 않는 런타임 결합을 데이터 경로에 신설한다 — 인가 판정의 지연 허용(토큰 수명)으로 살 수 있는 것을 가용성 결합으로 사는 것이다.

## Consequences

- **발급 경로에 제품→앱 호출 의존이 생긴다.** 앱이 죽으면 로그인·토큰 갱신이 실패하거나 권한 없는 토큰이 나온다(처리 방식은 코드 관할). 요청 경로가 아니라 발급 경로에 한정된 결합이다.
- **클레임은 발급 시점 스냅샷이다.** 권한 획득·동의 완료·회수의 발효가 토큰 갱신에 묶인다 — 상태 변경 직후 토큰 갱신을 트리거하는 것이 앱 흐름의 일부가 되어야 하고, 회수는 토큰 수명만큼 지연된다.

## 무효화 조건

- **제품 계열에서 발급 시점 클레임 주입이 불가능해지는 경우.** 이 결정은 발급 훅의 존재 위에 서 있다 — 훅 없이는 인가 데이터를 앱에 두면서 클레임 기반 판정을 할 수 없다.
- **인가가 리소스 단위로 세분화되어 클레임 스냅샷으로 표현할 수 없게 되는 경우.** 평평한 권한 목록이라는 전제가 깨지면 발급 시점 주입이 표현력을 잃는다 — 클레임 크기가 데이터에 비례해 자라고, 공유·회수에 기대되는 즉시 발효를 토큰 수명 지연이 감당하지 못한다.
