# obs-toolkit 어댑터 인터페이스 개선(②) — #127 측정 위에서 범위를 다시 정한다

## 1. 문제

부모 논의 `261019_1623` 은 ② 인터페이스 · 시그니처 개선 Task 를 왜곡 셋(주입구 · `RunResult` 튜플 · run 의 렌더)으로 그렸고, 4-10 에서 "#127 의 측정을 읽은 뒤 ② 의 Goal 범위를 정한다" 로 열어 두었다.
#127 이 끝났다 — mutation 생존 991 의 분류와 커버리지 미실행 33줄이 코멘트에 있다.
그 측정은 왜곡 셋 위에 셋을 더했다 — argv → `*Args` 매핑이 어느 티어에서도 검사되지 않는다(생존 101), 환경 · 시계 획득이 core 에 흩어져 있다(생존 14 + 미실행), 선언이 배선과 한 함수에 있다(생존 161).
조사 문서 `261022_1301` 이 일곱 결함과 그 묶임을 코드에서 읽었다.

이 논의가 정하는 것은 ② 의 **범위**다 — 일곱 중 무엇을 ② 가 고치고, 어디까지 고치고, 티켓 몇 개로 내나.
증상과 비용은 부모 §1 의 것이다 — 검수 시간과 거짓 안전감.
열려 있던 것은 넷이었다 — core 의 시그니처까지 건드리나, ② 가 끝났다고 보는 척도가 무엇인가, `doctor_main` 을 넣나, 티켓을 몇 개로 내나.
앞의 셋 중 둘은 인터뷰에서 닫혔고(척도 · doctor), core 경계와 티켓 모양은 옵션을 보고 정하기로 했다.

## 2. 실측

조사 문서 `261022_1301` 이 전부다. 결론에 쓰인 것만 옮긴다.

- 결함은 일곱이고 독립 묶음은 넷이다 — (① 주입구) · (② 매핑 + ⑥ 선언) · (③ 튜플 + ④ run 렌더) · (⑤ 환경 · 시계). ⑦ `doctor_main` 은 ① · ⑤ 의 doctor 판이고 ③ · ④ 와 무관하다.
- ③ 과 ④ 는 공동무효다 — `RunResult` 의 첫 필드 타입이 곧 run 의 반환 계약이다. run 이 받는 값 타입은 환원 열둘 + 원시 여섯.
- ② 매핑은 규칙 파일이 어느 티어에도 배정하지 않은 자리다. 기본값이 세 곳(`add_argument` · `getattr` · dataclass)에 중복되고 `--max-lines` · `--json` 은 Args 를 거치지 않는다. `*Args` 필드는 모두 58개(Promql 8 · Metrics 10 · Logql 9 · Logs 11 · Traceql 9 · Traces 11).
- ⑤ 의 절반은 이미 있다 — `finish` · `emit` 의 `env` 인자, `*_run` 의 `at` 인자. 진입점이 안 쓴다. 모자란 것은 core 의 `env is None` 분기 일곱과 `spill` 의 직접 시계 읽기다.
- ⑤ 를 core 까지 밀 때의 영향 범위 — `load_config` · `token_from_env` · `spill` · `spill_root` · `spill_ref` · `doctor` · `Client.from_env` 의 호출 자리가 obs 안에 14, tests 에 41(그중 `load_config` 20).
- 테스트의 결합 — 모듈 패치 17(`_client` 10 · run 4 · `doctor` 3) · 자리 읽기 33 · `setenv` 15 · `cli_env` 5 · `at=` 72.
- #127 의 생존 중 ② 가 구조로 없앨 수 있는 것 — 매핑 101 · run 전달 59 · 환경 14 · 시계 2 · `from_env` 19. 선언 161 은 분리 뒤 예외 설정으로 빠진다. 나머지(core 약속 누락 · 경계값 · 문구)는 ③ 의 것이다.
- 측정 환경 오염 — env 읽기를 깬 mutant 가 cwd 에 spill 해 `mutants/tmp/obs/` 에 디렉터리 22~28개를 남긴다(#127 측정 1 · 2). ⑤ 가 그 원인이다.

## 3. 인터뷰에서 닫힌 축

### 3-1. ② 의 척도 — 테스트 가능성 + 구조적 생존의 소거 + 선언의 분리

**선택: 셋 다.** 테스트가 모듈 패치 · 튜플 자리 없이 어댑터를 검사할 수 있고, #127 이 구조의 신호로 분류한 생존(매핑 · run 전달 · 환경 · 시계)이 테스트로 닫힐 수 있는 모양이 되고, argparse 선언이 배선과 분리된 자리에 있다. 부모 4-10 의 A 방향이다. (인터뷰, 2026-10-22)

<details><summary>버린 안</summary>

- 테스트 가능성만(부모 Goal 3-5 그대로) — 매핑 101 · 전달 59 가 남고 ③ 테스트 리팩토링이 그 자리에 테스트를 쓸 길이 없다.
- 잡음은 전부 예외 설정으로(부모 4-10 C) — 환경 획득 분기가 pragma 뒤에 영영 안 돈다.

</details>

### 3-2. ③ + ④ — 값까지 돌려준다

**선택: run 이 환원 값을 렌더 전 타입으로 돌려주고, 줄은 `finish` 가 만든다.** 반환 타입의 모양(제네릭 `RunResult[V]` 에 렌더러를 싣는가 · 서브커맨드별로 가르는가)은 작업자가 정하고 시나리오 색인의 선언에서 승인받는다. (인터뷰, 2026-10-22)

<details><summary>버린 안</summary>

- 이름만(③ 단독) — 자리 읽기 33은 사라지지만 run 층이 보는 것은 여전히 줄이라 전달 59 · `*_lines` 문구 단언 29 가 남는다.
- 작업자 재량 — "값으로 검사된다" 는 끝 상태이지 모양이 아니므로 Goal 에 적는 것이 맞고, 그 뒤의 모양은 어차피 재량이다. 선택지로서는 3-2 와 같다.

</details>

### 3-3. `doctor_main` — 넣는다

**선택: ② 에 넣는다.** `doctor_main(argv, env, transport)` — ① · ⑤ 와 같은 처방. `cli.doctor` 패치 3 이 사라진다. core `doctor` 의 생존 28(`Probe` 필드)은 core 의 약속이라 여기 밖이다. (인터뷰, 2026-10-22)

<details><summary>버린 안</summary>

- 뺀다 — 사람용이라 약속의 범위는 다르지만 결함의 꼴은 같다. 따로 내면 같은 처방을 두 번 승인한다.

</details>

### 3-4. ⑥ 선언 분리의 깊이 — 작업자 재량

**선택: Goal 에 "선언은 배선과 분리된 자리에 있다" 만 적는다.** 함수(`*_parser()`)로만 가를지 파일(`obs/adapters/parsers.py`)로 가를지는 작업자가 정한다. mutmut 예외가 파일 단위라는 사실은 Technical Notes 에 적는다. (인터뷰, 2026-10-22)

<details><summary>버린 안</summary>

- 파일 분리 강제 — 예외 한 줄을 위해 모듈 경계를 티켓이 정한다. 부모 4-7 의 "어떻게 고치나를 AC 로 못 박지 않는다" 와 어긋난다.
- 함수까지만 — 예외가 패턴으로 남는다. 그것도 작업자가 고를 수 있는 모양이다.

</details>

### 3-5. 시계 — 주입

**선택: 시계도 환경과 같은 처방이다.** `*_main` 이 한 번 읽어 `at: float` 로 내려보내고, `*_run` · `Window.last` 의 `None` 분기가 사라진다. `spill` 은 `at` 을 받는다. 조사 문서 §5 "시계" 가 세 길을 비교했다. (채팅, 2026-10-22)

<details><summary>버린 안</summary>

- 모듈 패치(`setattr(core, "now", …)`) — `cli.now` 도 따로, `spill` 의 `datetime.now` 는 못 잡는다. ① 과 같은 냄새.
- 동결 플러그인(`freezegun` · `time-machine`) — 시계 읽기 다섯 곳에 의존성 하나와 fork 환경 확인이 든다.

</details>

### 3-6. mutmut 예외 설정 — ③ 이 넣는다

**선택: 선언 161 을 분모에서 빼는 설정은 ③ 테스트 리팩토링이 넣는다.** 부모 4-1 대로 ② 머지 뒤 기준선을 다시 재는 자리가 ③ 이고, 예외 전 · 후 두 수치를 거기 남긴다. ② 는 소스만 바꾼다. (인터뷰, 2026-10-22)

<details><summary>버린 안</summary>

- ② 가 넣는다 — 선언의 자리가 정해지는 티켓이지만, ② 는 측정을 하지 않으므로 예외의 효과를 자기 코멘트에 남길 수 없다.
- 넣지 않는다 — 부모 4-10 D. 매 측정마다 161 을 다시 분류한다.

</details>

### 3-7. 완료 보고의 측정 — ②-a · ②-b 각각 끝에 mutation · 커버리지 결과를 코멘트에

**선택: 두 Task 모두 완료 보고 코멘트에 mutmut · coverage.py 결과를 싣고 #127 기준선과 mutant 이름 단위로 대조한다.** 구조 변경이 생존을 실제로 없앴는지가 그 자리에서 보여야 한다 — ③ 이 다시 재는 기준선과는 별개다. 예외 설정은 여전히 ③ 의 것(3-6). (채팅, 2026-10-22)

<details><summary>버린 안</summary>

- ② 는 측정하지 않고 ③ 이 기준선에서 본다 — 처음 초안. 구조 변경의 효과가 두 티켓 뒤에야 보이고, 어느 변경이 무엇을 없앴는지 가를 수 없다.

</details>

### 3-8. 진입점의 인자 — 필수, 조립은 shim

**선택: `*_main` 은 `argv` · `env` · `at`(시각 값) · `client`(Client 를 만드는 함수)를 필수로 받고, `None` 이면 안에서 읽는 분기를 두지 않는다. 프로세스를 읽는 곳은 `bin/*.py` 의 조립 한 줄뿐이다.** `x = read() if x is None else x` 는 테스트가 늘 값을 주므로 죽은 갈래이고, #127 의 환경 획득 생존 14 가 그 꼴이다 — 진입점에 같은 분기를 두면 자리만 옮긴 것이다. `client` 가 값이 아니라 함수인 이유는 argparse 뒤에 불러 `--help` · 인자 오류일 때 Client 를 만들지 않기 위해서다 — 토큰이 비어 있어도 usage 가 나온다. (채팅, 2026-10-22)

<details><summary>버린 안</summary>

- `*_main(argv, env=None, client=None, at=None)` 선택 인자 — 처음 초안의 모양. 분기 셋 × 일곱이 생존 자리가 된다.
- 타이머(`clock: Callable[[], float]`) 주입 — 아래 함수들이 각자 부르면 창과 호출 디렉터리 이름의 시각이 어긋난다. 진입점이 한 번 읽은 값 하나가 맞다.
- 조립을 `obs/` 안의 `run_cli(main)` 함수로 — 측정 대상 안에 읽을 수 없는 코드가 남는다. `bin/` 은 측정 밖이고 한 줄이다.

</details>

## 4. 열린 축 — 논의

### 4-1. ⑤ 의 범위 — core 의 `env=None` 기본값까지 없애나

실측 — core 의 `env is None → os.environ` 은 일곱 함수에 있고 호출 자리는 obs 14 · tests 41 이다. `finish` · `emit` 은 이미 `env` 를 받는다. 어댑터만 고치면 `setenv` 15 · `cli_env` 5 는 사라지지만 core 의 분기 자체는 남아 생존 14 가 그대로다 — 그 분기를 지나는 테스트가 없기 때문이다. `spill` 의 시계는 3-5 에 따라 어느 쪽이든 core 시그니처를 건드린다.

- A. 어댑터 + `spill` 의 시계만 — `*_main` 이 `env` · `at` 을 한 번 읽어 아래로 명시해 넘기고, core 는 `spill(…, at)` 만 바뀐다. ② 가 cli.py 에 머문다(부모 초안의 "core 시그니처 불변" 에 가장 가깝다). 이기는 조건 — ② 의 diff 를 어댑터로 묶어 두는 것이 검수에 더 중요할 때 / 지는 조건 — 생존 14 와 `from_env` 미실행이 남아 다음 측정마다 "구조의 신호" 로 다시 분류된다. 그 분기는 `bin/*.py` 경로에서만 돌고 어떤 테스트도 지나지 않는다.
- **B. 어댑터 + core 전부** — 일곱 함수의 `env=None` 기본값을 없애고 호출자 55곳이 `env` 를 넘긴다. 환경을 읽는 자리가 `*_main` 하나가 된다 — 부모 4-10 A 의 문장 그대로. 이기는 조건 — "환경 획득은 진입점에만" 을 구조로 강제하고 싶을 때(CLAUDE.md §8). 측정 환경 오염(`mutants/tmp/obs/`)도 원인이 사라진다 / 지는 조건 — core 시그니처 변경이 ② 를 어댑터 Task 에서 core Task 로 넓힌다. tests 41곳이 전부 수정된다 — 그중 `load_config` 20 은 `test_config.py` 의 것이라 어댑터와 무관한 파일이 갈린다.
- C. 안 한다 — ① 주입구만 넣고 ⑤ 는 두지 않는다. 이기는 조건 — 없다. `setenv` 15 가 남고 시계 주입(3-5)이 들어갈 자리가 없다. 현상 유지의 비용은 생존 16 + 측정 오염이다.

**판정(사람, 2026-10-22): B — 어댑터 + core 전부.** 환경을 읽는 코드는 `bin/*.py` shim 의 조립 한 줄만 남고(3-8), `*_main` 과 core 일곱 함수는 `env` 를 필수로 받는다. "진입점이 넘긴다" 를 관례가 아니라 타입으로 강제한다(CLAUDE.md §8). `test_config.py` 20곳의 수정은 ② 의 범위다.

### 4-2. 티켓의 모양 — 결함 일곱을 몇 개로 내나

실측 — 독립 묶음 넷 + doctor. 동작 AC 의 추정 — ① 주입(명시 · 미명시) 2행 · ⑤ 환경 · 시계 2행 · ⑦ doctor 1~2행 · ② 매핑은 "옵션이 core 에 닿는다" 가 CLI 경계의 동작이라 행이 될 수 있고 `*Args` 필드 58개가 그 상한이다 · ③+④ 는 구조라 동작 행이 없다(선언 그룹). 선행 의존 — ③+④ 의 typed 반환은 ① 없이도 되고, ② 매핑은 ⑥ 과 함께, ⑤ 는 ① 과 함께 간다. 부모 4-8 은 ② 를 "동작 1~2행" 으로 보고 tdd-loop 대상으로 판정했다 — 그 전제가 바뀌었다.

- A. Task 하나, 안에서 단위 넷 — tdd-loop 의 시나리오 색인이 단위 표를 가지므로 묶음 넷을 단위로 차례로 밟는다. 이기는 조건 — 선행 의존이 한 티켓 안에 살아 ADR-0017 의 선행 체인을 밖에 안 만들 때. 시나리오 승인이 한 번이다 / 지는 조건 — 동작 행이 ② 매핑 때문에 수십 행이 되면 한 번의 승인이 너무 커진다. PR 하나가 cli.py 1,253줄의 대부분을 바꾼다.
- **B. Task 둘 — 주입 · 환경 / 구조** — ②-a: ① ⑤ ⑦(테스트가 패치 없이 부를 수 있게). ②-b: ② ⑥ ③+④(무엇을 검사할 수 있게). b 는 a 의 후행. 이기는 조건 — a 의 diff 가 작고 기계적이라 먼저 머지해 ③ 의 기준선 일부를 앞당길 수 있을 때. 검수가 "꽂을 수 있나" 와 "볼 수 있나" 를 따로 읽는다 / 지는 조건 — 시나리오 승인 두 번, `*_main` 시그니처를 두 번 바꾼다(a 에서 `client · env · at`, b 에서 매핑 분리로 다시).
- C. Task 넷 — 묶음마다. 이기는 조건 — PR 하나가 한 결함만 말해야 할 때 / 지는 조건 — 승인 네 번, 선행 체인 셋, `*_main` 을 네 번 건드린다.
- D. 안 한다 — 부모 초안(왜곡 셋)대로 하나로 내고 나머지는 ③ 이 알아서. 지는 조건 — 3-1 을 되돌린다. ③ 은 테스트 티켓이라 매핑 함수를 꺼낼 수 없다.

## 5. 반대편 — 이 설계가 틀리는 조건

- ② 매핑을 순수 함수로 꺼내고 그 테스트를 contracts 에 두면, 부모 3-1 의 경계 표에 "매핑" 층이 없다. 표를 고치지 않으면 ③ 이 그 테스트를 경계 밖으로 보고 지운다. 3-1 표의 갱신이 ③ 초안에 들어가야 한다.
- typed 반환(3-2)이 `RunResult[Any]` 로 끝나면 pyright strict 가 값 타입을 모르고, 테스트가 `cast` 를 써야 한다. 그러면 "값으로 검사한다" 가 반쯤이다. 서브커맨드별로 가르면 반환 함수가 열둘이다. 둘 다 싫으면 ③ 단독이 맞았던 것이다 — 작업자의 시나리오 코멘트에서 드러난다.
- 4-1 B 를 고르면 `test_config.py` 20곳이 갈린다. 그 파일은 어댑터와 무관하고 ③ 의 범위도 아니다 — 누가 고치나가 비면 ② 가 떠안고 범위가 샌다.
- 매핑의 동작 행이 58개 필드만큼 나오면 tdd-loop 의 red 가 테스트 58개를 쓴다. 그것이 부모 §1 의 증상(테스트가 많아 검수가 느리다)을 다시 만든다. 행은 필드가 아니라 "옵션 종류(위치 · 플래그 · 기본값 있는 옵션)" 단위여야 한다.
- `*_main` 을 직접 부르는 테스트가 인자 넷을 전부 주게 된다 — conftest 헬퍼 없이는 장황하다. 시계를 `at: float` 필수로 바꾸면 `*_run` 을 직접 부르는 테스트 72곳은 그대로지만, `Window.last(since, end, at)` 의 `at` 기본값 제거는 core 시그니처라 4-1 의 A 를 골라도 core 가 두 군데(`spill` · `Window.last`) 바뀐다. "어댑터만" 은 정확히는 "core 는 시계 둘만" 이다.
- `*_main(argv, client, env, at)` 는 소비자가 늘면(#92 의 MCP 어댑터) 공개 API 가 된다 — 부모 §7 과 같은 감시 대상이다.
