# 모범 사례대로의 AI agent 병렬 작업은 사람에게 무엇을 하는가

## 1. 문제

AI agent가 보편화되면서 한 사람이 여러 agent 세션을 병렬로 돌리는 방식이 흔해지고 권장된다.
한편 agent 이전 시대의 통념은 사람의 병렬 작업이 효율을 떨어뜨리고 뇌 건강에도 나쁘다는 것이었다.
이 논의는 그 통념이 **모범 사례에 해당하는** agent 병렬 작업에 그대로 옮겨지는지를 묻는다.

열려 있던 것은 둘이다.
하나는 통념의 실제 근거가 얼마나 단단한가다.
다른 하나는 agent 병렬 작업에서 사람이 하는 일이 고전 연구가 측정한 "멀티태스킹"과 같은 종류의 일인가다.

병렬 agent 사용이 사람에게 미치는 영향을 직접 측정한 통제 연구는 조사에서 찾지 못했다.
그래서 이 문서의 종합은 두 문헌을 구조로 이어 붙인 추론이다.
출처가 직접 말한 것과 이 문서가 추론한 것을 구분해 적는다 — 추론에는 **(추론)** 을 붙인다.

## 2. 실측

근거 전문은 두 조사 문서에 있다.
여기에는 종합에 쓰인 것만 옮긴다.
이하 "연구 조사"는 `261120_1808_human-multitasking-research-survey.md`, "사례 조사"는 `261120_1809_ai-agent-parallel-work-practices-survey.md`다.

### 2-1. 통념의 실제 근거 — 강도를 보정하면

- 작업 전환 비용은 실재하지만 실험실 측정치는 전환당 수백 ms~1초 규모다(Rubinstein 2001, 연구 조사 §1).
- "생산 시간의 40% 손실", "집중 회복에 23분", "IQ 10점 하락", "뇌가 줄어든다"는 전부 원 출처가 뒷받침하는 범위를 넘는 인용이다(연구 조사 §9).
- "23분 15초"는 인지적 재몰입 시간이 아니라, 다른 일 약 2개를 거쳐 원래 일로 돌아오기까지의 경과 시간이다(연구 조사 §3.1).
- 미완료 과제를 두고 떠나면 다음 과제 수행이 떨어지고, 돌아갈 일을 예상하는 것만으로도 지금 과제가 나빠진다(Leroy 2009, Leroy & Glomb 2018).
- 짧은 "ready-to-resume" 계획이 그 저하를 완화한다(Leroy & Glomb 2018).
- 중단을 받으면 사람은 더 빨리 일해 시간·품질 손실을 메우고, 그 값으로 스트레스·좌절·시간 압박·노력이 오른다(Mark 2008).
- 급성 스트레스 반응은 교감신경 지표에서 확인되지만, 무작위 대조 시험(186명)에서 코르티솔과 면역 지표는 변하지 않았다(Becker 2023).
- 장기적 "뇌 건강" 손상을 인과로 보인 1차 연구는 찾지 못했다(연구 조사 §5).
- 멀티태스킹을 많이 하는 사람일수록 실제 능력은 낮고 자기 평가는 부풀려져 있었다(Sanbonmatsu 2013).
- 생산량은 멀티태스킹 수준에 대해 역U자이고 정확도는 단조 감소였다(Adler & Benbunan-Fich 2012).
- 하위 목표 완료 지점에서의 전환은 최악 시점보다 짜증을 56% 줄였다(Adamczyk & Bailey 2004).

정리하면 통념의 "효율 저하"는 방향은 맞고 크기는 과장되었다.
"뇌 건강" 쪽은 급성 스트레스까지만 근거가 있고 만성 손상은 근거가 없다.

### 2-2. 모범 사례가 사람에게 시키는 일

- 벤더들이 공통으로 드는 병렬 성립 조건은 작업 독립성, 격리(worktree·workspace), 명확한 범위·수용 기준, 자동 검증이다(사례 조사 §3).
- 사람의 승인 지점은 계획 승인, 권한 요청, PR 검토·머지다(사례 조사 §1.7).
- Claude Code agent view는 사람의 역할을 "step in only when one needs you"로 설계하고, 복귀는 알림, 검토는 요약 패널과 PR 상태로 한다(사례 조사 §1.1).
- 병렬 수의 구체 권고는 agent teams의 "Start with 3-5 teammates"가 유일하다(사례 조사 §1.1).
- 실무자 보고는 대체로 3~5이고(Willison 4, Osmani 3~4), 양 끝에 Hashimoto 1과 Yegge 20~30이 있다(사례 조사 §2).
- 실무자들이 지목하는 병목은 실행이 아니라 검토·감독이다(Willison "how fast I can review the results", Osmani "throughput of supervision").

즉 모범 사례에서 사람은 과제를 **수행**하지 않는다.
명세를 쓰고, 떠나 있고, 불려 오고, 검토하고, 승인한다.

### 2-3. 두 문헌을 잇는다 — 같은 것과 다른 것

| 고전 연구의 요소 | agent 병렬 작업에서 | 판단 |
|---|---|---|
| 사람이 두 과제를 번갈아 **수행**한다 | 사람은 수행하지 않고 **감독**한다 | 다르다 — task switching 실험보다 다중 자율 체계 감독 연구가 더 가까운 유비다 (추론) |
| 전환 시점을 외부(알림·동료)가 정한다 | agent 완료·권한 요청 알림이 정한다 | 같다 — 알림은 agent 쪽 경계에서 오지 사람 쪽 하위 목표 경계에서 오지 않는다 (추론) |
| 미완료 과제를 두고 떠난다 | 돌고 있는 agent 수만큼 미완료 과제가 상시 열려 있다 | 같거나 더 심하다 — attention residue의 조건이 구조적으로 충족된다 (추론) |
| 재개할 때 맥락을 다시 세운다 | agent가 한 일을 읽어 맥락을 세운다 | 다르다 — 내가 하던 일이 아니라 남이 한 일을 재구성한다. 명세·계획·요약 패널이 재개 단서 구실을 한다 (추론) |
| 드문 사건을 계속 지켜본다(vigilance) | 지켜보지 않고 알림으로 복귀한다 | 해당이 약하다 — 모범 사례는 상시 감시를 요구하지 않는다 |
| 자동화를 감독하며 다른 일을 한다 | 그대로다 | 같다 — automation complacency의 발생 조건(다중 과제 부하)과 일치한다 |

감독 연구 쪽이 말하는 것은 이렇다.

- 한 사람이 감독할 수 있는 자율 체계 수는 fan-out = NT/IT + 1로 모델링된다(Cummings & Mitchell 2008).
- 재정향·큐·상황 인식(SA) 상실로 생기는 대기 시간을 넣으면 그 용량은 최대 67% 줄고, 고도로 자동화된 예외 관리 방식에서도 36% 줄었다(같은 출처).
- 바쁜 시간 비율 70%가 성능 붕괴의 문턱으로 제안되었다(Cummings & Guerlain 2007).
- 여러 로봇을 감독할 때의 전환 비용은 감독 대상 수(4 대 8)가 아니라 자동화 수준이 높을 때 더 컸다(Squire & Parasuraman 2010).
- 자동화 아래의 수동적 정보 처리는 SA를 떨어뜨려 인수 성능을 낮춘다(Endsley & Kiris 1995).
- 자동화 안주와 자동화 편향은 전문가에게도 나타나고 연습·훈련·지시로 막히지 않는다(Parasuraman & Manzey 2010).

이것을 agent 쪽 관찰에 포개면 다음이 맞아떨어진다.

- NT는 agent가 혼자 달리는 시간, IT는 검토·재지시 시간에 대응한다 (추론).
  실무자들이 "병목은 검토"라고 말하는 것은 IT가 용량을 정한다는 모델과 같은 말이다.
- 실무자 보고 상한(3~5)은 자율 체계 감독 연구의 저하 지점(미사일 16기, 항공기 17대)보다 훨씬 낮다.
  코드 검토의 IT가 관제의 IT보다 길다고 보면 설명된다 (추론).
- agent가 더 자율적일수록 돌아왔을 때 재구성할 것이 많다는 Squire & Parasuraman의 결과는, 길게 방치한 agent일수록 검토가 무겁다는 실무 감각과 방향이 같다 (추론).
- 코드를 꼼꼼히 검토한다는 개발자의 61%가 agent 행동 일부를 면밀한 검토 없이 자주 승인한다는 설문(Wu 2026, 사례 조사 §4.2)은 자동화 안주의 예측과 일치한다.
- "더 빨리 일하고 더 지친다"(Mark 2008)는 ParallelPilot의 처리량 63% 증가와 Willison의 "by like 11 AM, I am wiped out"에 동시에 대응한다 (추론).
- 자기 평가가 부풀려진다는 결과(Sanbonmatsu 2013)는 METR 2025의 지각(20% 빨라짐)과 실측(19% 느려짐)의 괴리와 방향이 같다.
  METR 스스로 이 결과가 최신이 아니라고 표시했고, 2026년 후속 연구는 병렬 agent 사용자의 시간 측정 자체가 신뢰할 수 없다고 밝힌다.

고전 문헌에 대응물이 약한, agent 쪽 고유의 비용도 있다.

- 이해·기술 형성의 저하다.
  Anthropic RCT(n=52)에서 AI 그룹의 이해도 퀴즈 점수가 17% 낮았고, coding agent 연구(n=54)는 완료는 돕되 이해를 해친다고 보고했다(사례 조사 §4.4·§4.2).
  둘 다 단일 agent 연구이고 병렬은 다루지 않았다.
- 작업 범위·시간의 확장이다.
  작업 범위 확장과 멀티태스킹 증가, 근무 외·주말 작업 증가가 보고되었다(사례 조사 §4.5, 전부 2차 출처).

### 2-4. 영향도 종합

| 차원 | 방향 | 근거의 강도 | 모범 사례가 줄이는가 |
|---|---|---|---|
| 순간 수행(전환 직후의 속도·순서 오류) | 부정, 크기는 작다 | 고전 실험은 강하다. agent 맥락의 직접 측정은 없다 | 일부 — 작업 독립성과 격리가 과제 간 간섭을 줄인다. 전환 횟수는 줄이지 않는다 |
| 주의 잔여(열어 둔 과제가 지금 일을 갉는다) | 부정 | 실험 6건(Leroy). agent 맥락 직접 측정은 없다 | 일부 — 명세·계획 선행이 ready-to-resume 계획과 같은 구실을 할 수 있다 (추론) |
| 급성 스트레스·피로 | 부정 | 고전 실험이 강하고 실무자 보고가 같은 방향이다 | 거의 아니다 — 병렬 수를 낮추는 것 말고는 제시된 수단이 없다 |
| 만성 "뇌 건강" | 알 수 없다 | 인과 근거가 없다. 통념은 과장이다 | 해당 없음 |
| 처리량 | 긍정 가능 | ParallelPilot(n=16, 20분 블록)과 자기보고 설문. 지각은 실측과 어긋난 전례가 있다 | 그렇다 — 이것이 모범 사례의 목적이다 |
| 검토 품질(안주·편향) | 부정 | human factors 문헌이 강하고 2026년 설문이 일치한다 | 일부 — 자동 검증이 사람의 검토 누락을 받쳐 준다. 안주 자체는 훈련으로 막히지 않는다 |
| 이해·기술 형성 | 부정 | 소표본 RCT 2건, 단일 agent 대상 | 아니다 — 모범 사례는 처리량을 겨냥하지 이해를 겨냥하지 않는다. Copilot 문서는 배우려는 작업을 위임 부적합으로 분류한다 |
| 작업 시간·범위 확장 | 부정 | 2차 출처뿐이다 | 아니다 |

한 문장으로 줄이면 이렇다.
모범 사례는 통념이 말하던 비용 중 **과제 간 간섭**은 줄이지만, 사람의 일을 수행에서 감독으로 바꾸면서 비용의 자리를 **검토 용량·안주·이해**로 옮긴다 (추론).
"뇌 건강에 나쁘다"는 고전 쪽에서도 근거가 약했고, agent 쪽에서 확인되는 것은 피로와 수면에 관한 경험담까지다.

## 3. 인터뷰에서 닫힌 축

인터뷰는 하지 않았다.
아래는 요청이 처음부터 정해 준 것이다.

### 3-1. 논의의 성격

**선택: 순수한 자료 조사로 임한다.** 저장소 맥락 정찰과 인터뷰 없이 외부 문헌만으로 종합한다. (지시, 2026-11-20)

<details><summary>버린 안</summary>

- 사용자의 현재 작업 방식에 대한 인터뷰로 시작 — 요청이 명시적으로 뺐다
- 저장소의 하네스·ADR과 연결 — 맥락 파악이 불필요하다고 했다

</details>

### 3-2. 평가 대상

**선택: 모범 사례에 해당하는 병렬 작업만 평가한다.** 독립성·격리·명세 선행·자동 검증을 갖춘 병렬이 대상이다. (지시, 2026-11-20)

<details><summary>버린 안</summary>

- 조건을 갖추지 않은 병렬(같은 파일을 여러 agent가 고치는 등)까지 포함 — 벤더 문서가 이미 부적합으로 분류한 것이라 평가할 거리가 없다
- 단일 agent 사용의 영향 — 병렬의 영향이 아니다. 다만 직접 연구가 없어 단일 agent 연구를 근거로 빌렸다(§2-3)

</details>

### 3-3. 조사의 분담

**선택: 두 조사를 각각 별도의 opus subagent가 조사하고 직접 쓴다.** 종합은 두 조사 문서를 검토한 뒤 따로 쓴다. (지시, 2026-11-20)

## 4. 열린 축 — 논의

종합이 답을 주지 않고 사람에게 남기는 것 셋이다.
근거가 갈리거나, 근거가 말하는 방향이 벤더의 설계와 어긋나는 자리다.

### 4-1. 병렬 수

fan-out 모델로 보면 용량을 정하는 것은 검토 시간(IT)이고, 대기 시간을 넣으면 명목 용량이 36~67% 줄어든다.
생산량은 역U자, 정확도는 단조 감소였다.
실무자 보고는 3~5에 몰려 있고 Osmani는 "one thread less than feels right"라고 쓴다.

- A. 벤더 권고대로 3~5로 시작한다 — 작업이 독립적이고 자동 검증이 받쳐 주며 검토가 가벼울 때 이긴다 / 검토가 무거운 작업이 섞이면 검토가 밀리거나 얕아진다
- B. 체감 상한보다 하나 적게 잡는다(2~3) — 자기 평가가 부풀려진다는 근거를 받아들일 때 이긴다 / 대기 시간이 긴 작업뿐이면 놀리는 시간이 생긴다
- C. 수를 고정하지 않고 검토 대기 건수로 묶는다 — 병목이 검토라는 관찰에 가장 직접 대응한다 / 세기 위한 장치가 필요하고, 검토를 얕게 해서 건수를 줄이는 길이 열린다
- D. 병렬로 돌리지 않는다(순차, Hashimoto) — 이해·기술 형성이 목적인 작업이거나 중대한 변경일 때 이긴다 / 기계적이고 독립적인 작업에서는 처리량을 그냥 버린다

### 4-2. 복귀 방식 — 누가 전환 시점을 정하나

agent view와 Cherny는 알림으로 복귀하고, Hashimoto는 알림을 끈다.
고전 연구는 하위 목표 완료 지점의 전환이 덜 해롭고, 사람들이 알림을 받아도 하던 단위를 마무리하려 한다고 말한다.
한편 관찰 연구에서는 외부 중단 작업이 자기 중단 작업보다 더 빨리 재개되었다(p<.055).
알림의 27%가 이전 작업 창에서 2시간 넘게 이탈시켰다는 현장 연구도 있다.

- A. 알림으로 복귀한다 — agent가 막혀 있는 시간이 비쌀 때(권한 요청 대기 등) 이긴다 / 전환 시점이 내 과제 경계가 아니라 agent의 경계에 묶인다
- B. 알림을 끄고 내 과제 경계에서 둘러본다 — 그사이 내가 하는 일이 깊은 집중을 요구할 때 이긴다 / agent가 입력을 기다리며 서 있는 시간이 늘어난다
- C. 종류를 가른다 — 권한·질문 알림은 받고 완료 알림은 모아 본다 — A와 B의 비용을 각각 큰 쪽에서만 낸다 / 도구가 그 구분을 지원해야 한다
- D. 안 정한다(도구 기본값을 따른다) — 병렬 수가 낮아 알림이 드물면 충분하다

### 4-3. agent가 도는 동안 사람이 하는 일

METR은 참가자들이 agent를 기다리는 동안 무관한 작업을 했다고 보고한다.
자동화 안주는 수동 과제가 자동화 과제와 주의를 다툴 때 생긴다.
돌아갈 일을 예상하는 것만으로 지금 과제 수행이 떨어진다.

- A. 다른 agent에 지시하거나 다른 agent를 검토한다 — 처리량이 목표이고 작업이 전부 위임 가능한 종류일 때 이긴다 / 하루 전체가 감독이 되고, 피로 보고가 나온 것이 이 방식이다
- B. 깊은 집중이 필요한 내 일을 직접 한다 — 위임할 수 없는 설계·판단이 남아 있을 때 이긴다 / attention residue와 알림 중단이 그 일을 가장 직접 갉는다
- C. 가벼운 일만 한다(검토 준비, 다음 명세 작성) — 전환 비용이 작은 일로 대기 시간을 채운다 / 가벼운 일이 떨어지면 A나 B로 미끄러진다
- D. 아무것도 겹치지 않는다(지켜보거나 쉰다) — agent 실행이 짧을 때 이긴다 / 긴 실행에서는 vigilance 연구가 말하는 대로 지켜보는 것 자체가 부하다

## 5. 반대편 — 이 종합이 틀리는 조건

- 감독 유비가 깨질 수 있다.
  미사일·UAV 관제는 방치 비용이 실시간으로 커지지만 agent는 방치해도 멈춰 있을 뿐이다.
  NT가 사실상 무한이라면 fan-out 모델은 상한을 말해 주지 않고, 남는 제약은 검토 품질뿐이다.
- 실무자 보고는 강도 높게 쓰는 초기 사용자에게서 나왔다.
  피로와 수면 보고는 병렬 작업의 효과가 아니라 그 사람들의 사용 강도일 수 있다.
- 모델이 좋아지면 IT가 줄어든다.
  검토가 가벼워질수록 이 문서의 "병목은 검토"는 약해지고, 대신 안주의 비용이 커진다.
- 고전 연구는 대부분 실험실 과제·소표본·단기 측정이다.
  하루 종일, 몇 달에 걸친 감독 노동에 그대로 옮겨진다는 보장이 없다.
- 이해·기술 근거는 단일 agent·초급자·학생 대상이다.
  숙련자의 병렬 사용에서는 다를 수 있고, 같은 RCT에서 AI를 이해 형성에 쓴 사람은 점수가 높았다.
- 사례 조사의 일부 수치는 원문을 확인하지 못했다(Wu 2026의 세부 수치, ParallelPilot 후반부, Cherny·Yegge 원문).
  §2-3에서 쓴 61%와 63%는 조사 도구의 요약에 기댄 수치다.

## 6. 버린 것

- **"agent 병렬 작업은 뇌 건강에 나쁘다"를 결론으로 삼는 것.**
  고전 쪽 근거가 단면 상관과 오인용이고, agent 쪽에는 측정이 없다.
- **통념 수치(40%·23분·IQ 10점)를 agent 병렬의 비용 추정에 쓰는 것.**
  원 출처가 그 뜻이 아니다.
- **Weinberg 표로 병렬 수별 손실을 계산하는 것.**
  경험칙이고, 실증 점검은 과대 추정이라고 보고했다.
- **"모범 사례를 따르면 비용이 없다"는 결론.**
  모범 사례가 줄이는 것은 과제 간 간섭이고, 비용은 검토·안주·이해로 옮겨 간다.
- **task switching 실험을 주된 유비로 쓰는 것.**
  사람이 수행하지 않는 작업 방식이라 다중 자율 체계 감독 연구가 더 가깝다.

## 7. 임계선 — ADR감인가

ADR감이 아니다.
개인의 작업 방식이고, 병렬 수와 알림 설정은 그 자리에서 되돌릴 수 있다.
판정이 나면 갈 곳은 하네스 설정이나 작업 습관이다.

## 8. 다음

- §4의 세 축에 판정이 나면 그 자리에 한 줄씩 채운다.
- 직접 측정 연구가 없다는 것이 이 종합의 가장 큰 빈칸이다.
  사례 조사에서 열지 못한 것(ParallelPilot 후반부, Wu 2026 본문, CHI '26 "Code with Me or for Me?", Storey의 cognitive debt 논문)을 마저 읽으면 §2-4의 근거 강도 열이 바뀔 수 있다.
- 파생되는 ADR 초안과 티켓은 없다.
