# "문서화된 컨벤션이 지켜지지 않았다"는 거짓이었다 — 코드로 반증

---

## 1. 무엇이 주장됐나

프론트 리뉴얼 발산 과정에서 하나의 진단이 반복 인용됐다.

> 기존 프론트는 디렉터리 관례가 **문서로까지 정리돼 있었지만 지켜지지 않았고**, 결국 무너졌다.
> 그러므로 **문서화된 컨벤션은 강제가 아니다.**

근거로 지목된 문서는 `careerhub-front/CLAUDE.md` 의 한 줄이다 — *"각 페이지 디렉토리에 `index.svelte`(뷰), `api.js`(API 호출), `store.js`(상태 관리)가 함께 위치한다."*

이 진단은 세 문서에 박혔다: ADR-0012 · ADR-0015 · discussion `260717_2041`.

**사람이 이의를 제기했다** — *"저는 그런 관례를 만든 적이 없습니다."* 코드를 읽어 확인했고, **주장은 거짓이었다.**

---

## 2. 반증 — 세 겹

### ① 그 "문서"는 제정된 관례가 아니다

`careerhub-front/CLAUDE.md` 의 첫 줄:

```
This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.
```

`/init` 이 생성한 영문 보일러플레이트다. 저장소의 다른 모든 문서는 한글인데(루트 `CLAUDE.md` 의 언어 규칙) 이 한 줄만 영문인 것이 출처를 드러낸다.

문체도 명령이 아니라 **서술**이다 — *"…가 함께 위치한다"*, *"테스트 프레임워크는 설정되어 있지 않다"*. 지켜야 할 규칙을 정한 것이 아니라 **이미 있는 구조를 읽고 받아적은 것**이다.

커밋도 이를 뒷받침한다. `e759172` — 메시지는 *"약관 동의 API를 signIn에서 분리하고 RequireAgreement에서 직접 처리하도록 변경"*. 컨벤션 제정 커밋이 아니라 **기능 커밋에 딸려 들어갔다.**

> **관례를 세운 문서가 아니라, 관례를 관찰한 문서였다.** 이 차이가 "강제가 아니다"라는 결론의 전제를 통째로 없앤다 — 강제할 의도로 쓰인 적이 없다.

### ② 시간 순서가 인과를 부순다

| 시점 | 사건 |
|---|---|
| 2024-09 ~ 2025-06 | 실질적 프론트 코드 전부. 마지막 기능 커밋 `8c9ef1d` (2025-06-09) |
| **2026-03-30** | **`CLAUDE.md` 최초 등장** (`e759172`) |
| 2026-03-30 이후 | CI 워크플로우 커밋 하나(`0853440`)뿐 |

**문서가 코드보다 9개월 늦다.** 문서 이후에 작성된 프로덕션 코드가 사실상 없다.

*"문서화된 컨벤션이 지켜지지 않았다"* 가 참이려면 **문서가 있는 동안 그것을 어긴 코드**가 있어야 한다. 그런 기간이 존재하지 않는다. 명제는 거짓이기 이전에 **성립하지 않는다.**

### ③ 게다가 그 관례는 지켜지고 있다

`src/view/` 하위 페이지 디렉터리 전수:

```
job_posting/            api.js  index.svelte  store.js
job_posting/postingId/  api.js  index.svelte  Detail.svelte
login/                  api.js  index.svelte  store.js
my/authority/           api.js  index.svelte
my/match-job/           api.js  index.svelte
my/scrap-job/           api.js  index.svelte
my/withdrawal/          api.js  index.svelte
admin/ticket/           api.js  index.svelte
admin/user/             api.js  index.svelte
```

**예외가 없다.** 모든 페이지 디렉터리에 `index.svelte`, API 호출이 있는 곳에 `api.js`, 상태가 있는 곳에 `store.js`.

실제로 흔들리는 것은 **디렉터리 명명**이다 — `add_authority`(스네이크) · `match-job`(케밥) · `jobPostingList`(카멜). 그러나 `CLAUDE.md` 는 명명 규칙을 **말한 적이 없다.** 따라서 이것도 "어긴 컨벤션"이 아니라 **애초에 없던 컨벤션**이다.

## 3. 무엇이 무너지고 무엇이 서 있나

**무너진 것: 논거.** *"관례가 있었는데 안 지켜졌다 → 문서는 강제가 아니다"* 라는 경로. 전제가 거짓이므로 이 경로로는 아무것도 지탱되지 않는다.

**서 있는 것: 결론.** 다만 **다른 사실 위에서** 선다.

진짜 사실은 *"관례를 어겼다"* 가 아니라 ***"관례가 아픈 곳을 아예 다루지 않았다"*** 이다.

| 아픔 | 코드의 사실 | `CLAUDE.md` 가 다루나 |
|---|---|---|
| 컴포넌트 비대 | `Detail.svelte` 914줄 · `JobPostingItem.svelte` 479줄 (svelte 32개 합 4,950줄) | ❌ 한 줄도 없다 |
| 스타일 흩어짐 | 32개 중 **23개**가 자체 `<style>` 보유 · 토큰 없음 | ❌ 한 줄도 없다 |
| 회귀를 못 잡음 | 테스트 없음 | ⚠ *"테스트 프레임워크는 설정되어 있지 않다"* — **서술할 뿐, 요구하지 않는다** |

**디렉터리 배치는 지켜졌고, 그리고 안 아팠다.** 아픈 셋은 어떤 관례도 언급조차 하지 않은 영역이다.

> **교정된 교훈:** 문서화된 컨벤션이 배신한 것이 아니다. **컨벤션이 아픈 축을 덮지 않았다.**
> "구조로 강제하라"는 결론은 여전히 서지만, 그 이유는 *"글로 적어도 안 지켜지니까"* 가 아니라 ***"글이 다룬 축은 안 아팠고, 아픈 축은 글이 다룬 적이 없으니까"*** 다.

**이쪽이 더 강한 근거다.** 전자는 "사람이 규율을 안 지킨다"는 일반론이라 반례에 약하다. 후자는 **이 코드베이스에서 검증된 사실**이고, 무엇을 강제할지까지 지목한다 — 배치가 아니라 **크기·스타일·회귀**.

## 4. 이 반증이 왜 여기 있나 — 각 문서의 처분

| 문서 | 상태 | 처분 | 왜 |
|---|---|---|---|
| **ADR-0012** | `accepted` · 공표됨 → **동결** | **결정 유지. 본문 손대지 않는다** | 아래 |
| **ADR-0015** | `proposed` (가변) | **Context 재작성** | 전제가 Context 의 뼈대였다 |
| discussion `260717_2041` | `active` | 원문 보존 + 반증 표시 | 사고의 기록은 지우지 않는다 |

**ADR-0012 를 supersede 하지 않는 이유.** 거짓인 것은 Context 의 **보조 논거 한 줄**이지 Decision 이 아니다. Next.js 채택은 이 줄 없이도 선다 — §3의 교정된 교훈이 오히려 더 곧게 받친다. 부분 supersede 는 불허이므로(CLAUDE.md §3) 이 한 줄을 고치려면 **결정 전체를 폐기하고 재진술**해야 하는데, 결정이 멀쩡한데 결정을 죽이는 것은 비용이 값에 안 맞는다.

**대신 반증을 지식 플레인에 남긴다.** ADR-0012 를 읽는 다음 사람이 그 줄을 인용하기 전에 이 문서를 만나야 한다 — 그것이 이 문서의 존재 이유다.

> **동결은 "틀린 것을 영원히 참으로 두는 것"이 아니다.** 결정의 의미가 얼 뿐, 그 논거에 대한 후속 지식은 계속 쌓인다. 얼어붙은 ADR 위에 반증을 얹는 방법은 **본문 수정이 아니라 새 문서**다.

## 5. 남는 물음 — 이 문서를 `done` 으로 닫지 않는 이유

**① 다른 곳에 같은 전제가 있나.** ADR-0013·0014 는 확인했고 **깨끗하다** — 둘 다 *"사람의 코드 리뷰를 품질 보증의 근거로 두지 않는다"* 는 별개 전제에 얹혀 있다. 그러나 이후 문서가 ADR-0012 L25 를 다시 인용할 위험은 남는다.

**② 왜 이 거짓이 세 문서까지 갔나.** 반증이 쉬웠다 — `git log` 한 번이면 시간 순서가 드러났다. **그런데 아무도 돌리지 않았고, 사람이 읽고서야 걸렸다.** 이것은 이 발산 과정 자체에 대한 관찰이며, ops-workflow 의 마찰 로그로 갈 재료다.

> *"기존 프론트가 그 증거다"* 라고 쓸 때, **그 증거를 실제로 열어보지 않았다.** 코드가 있는데 추측으로 단언한 것 — CLAUDE.md §2가 *"desired 는 코드가 답한다"* 고 정한 바로 그 지점에서 어긋났다.

**③ 강제할 축이 다시 열리나.** §3의 교정된 교훈은 강제 대상을 **크기·스타일·회귀**로 지목한다. ADR-0015 는 이 중 스타일만 다룬다. 나머지 둘(컴포넌트 크기 · 회귀)이 각각 결정을 필요로 하는지는 아직 안 정해졌다.
