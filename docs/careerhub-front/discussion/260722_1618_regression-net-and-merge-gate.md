# 회귀를 무엇이 잡나 — 그리고 그물이 무언가를 실제로 막나

ADR-0012 는 *"타입·계약·테스트를 선택이 아니라 전제로 만든다"* 고 했다. 셋 중 **타입은 ADR-0013**, **계약은 ADR-0014** 가 받았다. **테스트만 받는 문서가 없다.**

ADR-0011 이 재작성을 정당화한 세 아픔 중 하나도 *"회귀를 잡을 그물이 없다"* 였다. 스타일은 ADR-0015 가 받았고, 크기는 티켓으로 내려갔다. **회귀는 아직 아무 데도 없다.**

이 문서는 그 빈자리를 벌린다.

---

## 1. 코드에서 읽은 것

### 이 집의 테스트 관례

앞선 발산(`260717_2041` §6-E)은 *"프론트에 테스트 프레임워크가 없다"* 까지만 확인하고 백엔드는 안 봤다. 봤더니 그림이 다르다.

| 사실 | 근거 |
|---|---|
| 프론트에 테스트가 **없다** — 스크립트도 의존성도 | `careerhub-front/package.json` — `build`·`dev`·`start` 셋뿐 |
| **백엔드에는 있다** — 6개 서비스에 `*_test.go` **43개** | auth-service 8 · posting-service 17 · userinfo 6 · api-composer 5 · review 5 · skillscanner 2 |
| 그것도 **진짜 의존성을 띄워서 돈다** | `auth-service/test/tinit/tinit_db.go` — `testcontainers-go` + `modules/postgres` |
| 별도 테스트 compose 까지 있다 | `auth-service/docker-compose.test.yml` |
| 실행은 `make test` — **타임아웃 600초** | `auth-service/Makefile:64-67` |
| **★ 어느 저장소에도 PR 게이트가 없다** | 10개 저장소 전부 `.github/workflows/create-tag.yaml` 하나 — 태그 푸시 → 이미지 빌드 |

**★★ 이 집의 사실은 이렇다: 테스트는 43개 있고, 그중 하나도 머지를 막지 않는다.**

### 프론트가 실제로 하는 일

| 사실 | 근거 |
|---|---|
| 라우트 **12개** — 공개 4 · 인증 8 | `src/view/index.js` 전수 |
| **순수 로직이 38줄뿐** — base64 쿼리 인코딩, 페이지네이션 파싱 | `src/components/query/utils.js` |
| 나머지 ~5,800줄은 **표시 + 배선** | `.svelte` 4,950 + 얇은 fetch 래퍼 |
| 비즈니스 로직은 백엔드에 있다 — 3-way fan-out · 스킬 추출 · 리뷰 결합 | api-composer · skillscanner · review-service |

> **★ 그러므로 이 앱에서 프론트의 회귀는 대개 *"배선이 끊어졌다"* 이지 *"계산이 틀렸다"* 가 아니다.** 순수 함수로 검증할 수 있는 표면이 전체의 1% 미만이다. 무엇을 어느 층에서 잡을지가 이 사실에 크게 좌우된다.

## 2. 축이 잘못 놓여 있었다

**"테스트를 쓰는 사람인가"는 질문이 아니었다.** 백엔드에는 쓴다. 무거운 인프라(testcontainers · 600초)도 감수한다. **프론트에만 없고**, 그 이유는 규율이 아니라 ADR-0012 가 이미 인정한 것 — 사람이 프론트를 못 다룬다 — 에 가깝다.

그리고 백엔드의 테스트조차 **로컬에서만 돈다.** 아무도 돌리지 않아도 배포된다.

> **진짜 축은 "테스트를 쓰나"가 아니라 ***"그물이 무언가를 실제로 막나"*** 다.**

이건 이 저장소의 관통 원칙과 같은 문장이다 — *"규율이 아니라 구조로 강제한다."* 그리고 ADR-0013·0015 가 **이미 여기에 기대고 있다.** 0015 는 Decision 에 *"그 이탈은 린트에서 거부한다"* 고 적었고, 0013 은 타입 검사가 실행 전에 막는다고 했다. **거부할 자리가 지금 없다.**

## 3. 두 개가 뭉쳐 있다 — 회귀 그물과 수용 검사

| | **회귀 그물** | **수용 검사** |
|---|---|---|
| 묻는 것 | *"고쳤더니 다른 게 깨졌나"* | *"agent 가 만든 것이 요구를 만족하나"* |
| 없을 때 | 손을 못 댄다 (ADR-0011 의 아픔) | agent 가 만든 것을 아무도 못 읽는다 (ADR-0012 의 대가) |
| 재작성 중 | **대상이 있다** — 기존 앱이 돌고 있다 (아래 정정) | **지금 필요하다** |
| 재작성 후 | **필요해진다** | 계속 필요하다 |
| ADR-0011 의 처분 | — | *"사람이 확인한다"* 로 이미 정해졌다 |

**★ ADR-0011 이 답한 것은 수용 검사 쪽이다.** *"동작 동등성을 기계가 보증하지 못한다 — 사람이 확인한다."* 그건 **재작성 기간의 판단**이고, 회귀 그물의 부재를 승인한 것이 아니다.

> **⚠ 이 절의 초판은 *"재작성 중엔 회귀할 과거가 없다"* 고 적었다. 틀렸다.** 기존 앱이 돌고 있다. **기존 앱의 동작이 명세의 출처가 될 수 있다**(§5.5). 이 오류가 "명세 선행"이라는 선택지를 통째로 시야에서 지웠다.

→ **이 축이 다루는 것은 회귀 그물이다.** 다만 §5.5 가 보여주듯 두 목적은 **한 산출물로 동시에 만족될 수 있다.**

## 4. ★★ 이 프로젝트 특유의 함정 — 누가 테스트를 쓰나

ADR-0012 가 받아들인 대가는 *"사람이 리뷰로 품질을 보증하지 못한다"* 였다. 그런데 그 사실이 여기에도 그대로 적용된다:

> **테스트도 agent 가 쓴다. 즉 agent 가 쓴 테스트가 agent 가 쓴 코드를 검증한다.**

같은 오해가 양쪽에 복제되면 **테스트는 통과하고 화면은 깨진다.** 사람이 리뷰로 그것을 걸러줄 수 없다는 것이 이 프로젝트의 전제다.

**그래서 층을 고르는 진짜 기준이 나온다 — 기준이 구현에서 파생되는가.**

| 층 | 기준의 출처 | 순환 위험 |
|---|---|---|
| **컴포넌트/유닛** | agent 가 쓴 구현 | **가장 높다** — 구현을 그대로 어서션으로 옮기기 쉽다 |
| **브라우저 e2e·스모크** | **화면이 실제로 뜨는가** | 낮다 — 구현 내부를 안 본다 |
| **생성 타입** | **백엔드 스펙** | 없다 — **ADR-0014 가 이미 담당한다** |
| **★ 기존 앱에 대고 쓴 명세** | **기존 앱의 동작** | **없다** — 새 코드가 존재하기 전에 쓰인다 (§5.5) |

> **★ 구현에서 파생되지 않는 기준만이 이 프로젝트에서 값을 낸다.** ADR-0014(백엔드 스펙에서 타입 생성)가 값진 이유도 정확히 이것이었다 — 손으로 쓴 것은 거짓말할 수 있고, **손으로 쓴 테스트도 같다.**

이 관점이 앞선 발산에 없었다. 넣으면 층의 순위가 뒤집힌다 — 싸다는 이유로 컴포넌트 테스트를 먼저 두면, **가장 순환 위험이 큰 것을 먼저 세우는 것**이 된다.

## 5. ★★ 시점과 층은 독립이 아니다

앞선 판에서 ①시점(T1/T2)과 ②층을 별개 축으로 놓았다. **얽혀 있다.**

*"나중에 붙이면 테스트 불가능하게 지어진 코드를 고쳐야 한다"* — 이 명제의 참·거짓이 **어느 층이냐에 따라 갈린다.**

| 층 | 나중에 붙이는 비용 | 왜 |
|---|---|---|
| **컴포넌트/유닛** | **비싸다** | 데이터 페칭을 갈아끼울 자리가 있어야 한다. 없으면 구조를 뜯는다 |
| **e2e·스모크** | **싸다** | **구현 내부를 안 본다.** 화면 밖에서 URL 을 열고 요소를 확인할 뿐 |

> **★ e2e 중심으로 가면 "지금 결정해야 한다"는 압박이 사라진다.** 그리고 그 압박이 이 축을 ADR 후보로 만든 유일한 근거였다(ADR-0013 의 *"처음부터 결정한다"* 논리와 동형이라는 것).

**e2e 를 나중에 붙일 때의 숨은 비용은 따로 있다** — 정직하게:

- **안정적인 선택자.** 마크업이 바뀔 때마다 깨지지 않으려면 test id 같은 것이 필요하고, 그건 **화면을 지을 때 넣는 게 싸다.** ADR-0015(Tailwind)로 클래스가 스타일 전용이 되면 클래스 선택자는 더더욱 못 쓴다.
- **결정적인 데이터.** 공고 수집이 **CronJob 으로 하루 한 번** 돈다(`jyoliar-k8s/.../jobs/cronjob.yaml`). 실데이터에 의존하면 테스트가 매일 흔들린다 → 시드·픽스처가 필요하고, **그건 백엔드 일이다.**
- **로그인 진입점.** 12 라우트 중 8 이 인증 → **#7 이 전제.**

→ **"e2e 는 나중에 붙여도 싸다"가 참이려면 위 셋 중 앞 둘을 지금 준비해야 한다.** 그 둘은 테스트 자체가 아니라 **테스트가 붙을 자리**다.

## 5.5. ★★ 빠져 있던 선택지 — 명세를 먼저 쓴다

§3 의 오류(*"회귀할 과거가 없다"*)가 이 선택지를 시야에서 지웠다. **기존 앱이 돌고 있다.** 그러면 재작성 **전에** 그것에 대고 e2e 명세를 쓸 수 있고, 새 앱은 그 명세를 통과시키는 방향으로 지어진다.

### 무엇이 달라지나

- **순환이 끊긴다**(§4). 명세가 **새 코드가 존재하기 전에** 쓰이므로 agent 가 자기 구현을 어서션으로 옮길 수 없다. 지금까지 찾은 "구현에서 파생되지 않는 기준" 중 **가장 강하다.**
- **ADR-0011 이 사람에게 맡긴 자리를 기계가 채운다.** *"동작 동등성을 기계가 보증하지 못한다"* 는 **"회귀 그물 없이 시작하므로"** 라는 전제 위의 예측이었다. 전제를 바꾸면 예측이 빗나간다 — **좋은 쪽으로.** 결정(재작성한다) 자체는 건드리지 않으므로 supersede 사안이 아니다.
- **수용 검사와 회귀 그물이 한 산출물이 된다**(§3). 재작성 중엔 수용 검사로, 끝난 뒤엔 회귀 그물로 쓰인다.

### 함정 셋

**① 기존 동작을 굳히면 나쁜 동작까지 굳는다.** 이건 리뉴얼이다 — 디자인을 새로 정립하려는 것(ADR-0015). 기존 화면 구조에 밀착한 명세는 **새 디자인을 거부하는 그물**이 된다.

→ 명세를 **사용자 의도** 수준으로 써야 한다. *"공고를 검색해 상세로 들어가 스크랩한다"* 는 살아남고 *"사이드바 세 번째 체크박스"* 는 안 된다. **그런데 그 추상 수준을 유지하는 것은 규율이고, 이 저장소의 §8 은 규율을 믿지 말라고 한다.** 이 긴장은 안 풀렸다.

**② 재사용되는 것은 시나리오이지 코드가 아니다.** 기존 앱의 선택자는 새 앱에 없다. 명세는 남고 구동 코드는 다시 쓴다.

**③ "최대한"이 위험한 말이다.** 쓸 수 있는 것은 **바뀌지 않을 것**뿐이다 — 라우트, 데이터 흐름, 핵심 사용자 여정. 레이아웃·디자인은 아직 안 정해졌으므로 못 쓴다. 문자 그대로 "최대한"을 하면 **모르는 것을 미리 정하는** 실패가 된다.

### ★ 이것이 다른 미결을 같이 푼다

명세를 **흐름 단위로** 쓰면 그것이 곧 **재작성의 쪼갬**이다. 각 명세가 그 Task 의 완료 조건이 된다. → §9 미결 ②(재작성 Task 가 하나도 안 쪼개져 있다)가 여기서 닫힌다.

## 6. 옵션 — 다시 놓은 것

| | 무엇 | 잡는 것 | 비용 | 순환 위험(§4) |
|---|---|---|---|---|
| **N0. 없음** | — | — | 0 | — |
| **N1. 라우트 스모크** | 12개 라우트가 뜨고 핵심 요소가 존재하나 | **배선 회귀** — 이 앱의 회귀 실체(§1) | 중간 (#7 필요) | 낮다 |
| **N2. 핵심 흐름 e2e** | 검색→필터→상세→스크랩 | 사용자 관점의 회귀 | 크다 (스택 기동 · 시드) | 낮다 |
| **N3. 순수 로직 유닛** | 쿼리 인코딩·페이지네이션 | 계산 오류 | **거의 0** | 중간 |
| **N4. 컴포넌트 테스트** | 컴포넌트 단위 | 렌더 회귀 | 작다 | **높다** |
| **N5. 시각 회귀** | 스타일 변화 | 스타일 회귀 | 중간 | 낮다 |
| **★ N6. 명세 선행** | 기존 앱에 대고 e2e 명세를 **먼저** 쓴다 | **동작 동등성 + 회귀** | 착수가 늦어진다 | **없다** (§5.5) |

**N3 은 대상이 38줄뿐이다** — 싸지만 값도 그만큼이다. **N5 는 디자인을 바꾸는 동안 노이즈다.**

**★ N1 이 이 앱의 회귀 실체(§1)와 가장 잘 맞는다.** 배선이 끊어진 것을 잡는 데 전체 스택 e2e 가 필요하지는 않다.

### 인프라 범위 — N1·N2 의 하위 선택

| | 무엇 | 잡나 |
|---|---|---|
| **전체 스택** | auth · api-composer · 코어 3 · Mongo 3 | 계약 위반까지 |
| **백엔드를 가짜로** | 프론트만 + 응답 모사 | 배선만. **계약은 ADR-0014 가 담당** |

**후자가 §4 의 순환 위험을 조금 들여온다** — 가짜 응답을 agent 가 쓰기 때문이다. 다만 **그 응답의 형태를 백엔드 스펙에서 생성하면**(ADR-0014) 순환이 끊긴다. **두 결정이 여기서 만난다.**

## 7. 게이트 — 계층화된다

**§2 가 이 축을 강제로 연다.** 그물이 있어도 아무것도 막지 않으면 규율이지 구조가 아니다.

| | 되돌리기 | 트레이드오프 |
|---|---|---|
| **G0. 아무것도 안 막는다** (지금) | — | 백엔드가 이 상태다 |
| **G1. PR 필수 통과** | **쉽다 — 워크플로 파일 하나** | 타입·린트가 실제로 막는다 |
| G2. 로컬 훅 | 쉽다 | `--no-verify` 로 우회 가능 — 규율에 가깝다 |

**빠른 것과 느린 것을 같은 문에 두지 않는다.** 타입·린트·유닛은 PR 에서 초 단위로 끝나고, e2e 는 스택을 띄워야 한다. 흔한 배치는 **PR 에 빠른 것 · 머지 후나 야간에 느린 것**이고, 되돌리기가 싸므로 이건 결정이 아니라 설정이다.

**→ 축 ③은 ADR 이 아니라 티켓이다**(§4②). 그러나 **ADR-0013·0015 의 강제력이 여기 걸려 있다**(§2).

## 8. 수렴 신호 점검

- **새 옵션이 더 나오나** — §6 표에서 멈췄다. N0~N5 가 층을 덮는다
- **각 옵션이 어떤 조건에서 이기는지 말할 수 있나** — 말할 수 있다. N4 는 순수 로직이 두꺼울 때 이기는데 여기선 38줄이다. N2 는 흐름이 복잡할 때 이기는데 이 앱은 12 라우트다. **N1 이 이 앱의 형상과 맞는다**
- **남은 이견이 사실 문제인가** — §5 의 "e2e 를 나중에 붙이는 비용"은 사실 문제이고, 위에서 셋으로 특정됐다

### ★ 그래서 임계선 판정

§5 가 이 축의 ADR 후보 자격을 깎았다. **e2e·스모크 중심이면 되돌리기가 싸고, 그러면 §4② 임계선을 넘지 않는다 → 티켓이다.**

**단 하나가 남는다** — *"테스트가 붙을 자리"*(안정적 선택자 · 결정적 데이터)는 **재작성 중에 준비해야 싸다.** 그건 결정이 아니라 **재작성 Task 의 수용 조건**에 가깝다. 축 D 에서 #8 이 한 것과 같은 모양이다.

>
> **그동안의 운영 방침**: 두 앱 배선 모두 **실환경 겨눔 + 불변식 어서션**으로 관리한다. 통제하는 것은 데이터의 *내용*이 아니라 *존재*다. 따라서 **e2e는 차단 게이트가 될 수 없다** — 빨간불이 앱 회귀인지 데이터 변동인지 구분되지 않는다. (#9 본문에 반영)

## 10. 지금까지의 관찰

- **★★ 이 집에는 테스트가 43개 있고 그중 하나도 머지를 막지 않는다.** "테스트를 쓰는가"는 이미 참이고, 빠진 것은 **구조**다.
- **★ 발산 기록이 프론트만 보고 "테스트가 없다"고 규정했다.** 백엔드를 봤으면 축이 처음부터 다르게 놓였다.
- **★★ agent 가 쓴 테스트가 agent 가 쓴 코드를 검증한다**(§4). 이 프로젝트에서 **기준이 구현에서 파생되면 검증이 아니라 반복**이다. ADR-0014 가 "손으로 쓴 타입은 거짓말한다"고 한 것이 테스트에도 그대로 성립한다 — **그런데 아무도 그 대칭을 안 봤다.**
- **★★ 시점과 층이 독립이 아니었다**(§5). "나중에 붙이면 비싸다"는 층에 따라 참이기도 거짓이기도 하다. **두 축을 따로 놓은 것이 이 축을 실제보다 크게 보이게 했다.**
- **★ ADR-0011 이 답한 것은 수용 검사이지 회귀 그물이 아니다**(§3). 두 목적이 "테스트"라는 한 단어에 뭉쳐 있었다.
- **★ 프론트의 순수 로직이 38줄이다**(§1). 유닛 테스트가 값을 낼 표면이 거의 없다는 사실이 층의 순위를 정한다 — **코드를 세어보기 전에는 "테스트 = 유닛 테스트"로 상상하게 된다.**
- **ADR-0013·0015 가 존재하지 않는 게이트에 기대고 있다**(§2·§7). 초안 심사에서 물어야 할 지점.
- **이 축의 결론은 "ADR 이 아니다"로 기운다**(§8). **발산이 결정을 만들지 않고 없앤 사례** — 축을 제대로 놓으니 임계선 아래로 내려갔다. **N6(명세 선행)도 이 판정을 바꾸지 않는다** — 쓰다 말면 버리면 되므로 되돌리기가 싸다. **결정처럼 느껴지는 것과 ADR 인 것은 다르다. 임계선은 무게가 아니라 되돌리기 비용이 정한다.**
- **★★ 한 문장의 오류가 선택지 하나를 통째로 지웠다**(§3·§5.5). *"재작성 중엔 회귀할 과거가 없다"* — 기존 앱이 돌고 있는데 그렇게 썼다. **명세 선행은 사람이 물어서야 나왔다.** 옵션 표를 다 채웠다는 느낌이 빈자리를 덮었다.
- **★ 순환을 끊는 기준의 출처가 셋이 아니라 넷이었다**(§4). 브라우저 · 백엔드 스펙 · **기존 앱의 동작**. 셋째가 가장 강한데 가장 늦게 나왔다 — **버리려는 것 안에 검증의 원천이 있었다.**
