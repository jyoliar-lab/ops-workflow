# 은퇴한 환경(aws-ec2) 코드의 보존 방식

## 문제

aws-ec2는 라즈베리파이 홈랩 구축 전의 모의 구축 환경으로 현재 존재하지 않는다. 그런데 관련 코드(`jyoliar-k8s/gitops/overlays/aws-ec2/` 트리, `onpremise-k8s/kubernetes/inventory/aws-ec2` 파일)가 HEAD에 baremetal과 형제로 남아 있어, 코드를 읽는 agent·사람이 실존 환경으로 반복 오인한다.

§2의 언어로: **desired는 코드가 답하는데, 지금 HEAD가 "환경이 둘"이라는 거짓을 답하고 있다.** 목표는 둘이고 서로 당긴다 — (a) HEAD가 진실만 말하게 하기, (b) 멀티환경 지원 패턴의 참고 가치 보존.

## 코드에서 확인된 사실 (논의의 축을 바꾼 것)

- **이미 drift가 시작됐다.** baremetal root-appset에는 `services` root가 있으나 aws-ec2에는 없다. 한편 최근 커밋(a3a76e4 등)은 aws-ec2 overlay를 *함께* 수정하고 있다 — 죽은 환경에 유지보수 비용을 부분적으로만 내면서 썩는, 최악의 중간 상태. **"HEAD에 두면 참고 가치가 보존된다"는 전제 자체가 거짓으로 판명.**
- **오인의 절반은 파일이 아니라 두 저장소의 CLAUDE.md다.** aws-ec2를 현행 예시로 가르친다(환경명 예시·트리 예시·deploy.sh usage). 어느 옵션을 골라도 이 정리는 공통 작업.
- onpremise-k8s는 "인벤토리 파일명 = 환경명" 규약이라, 파일 존재가 곧 환경 존재로 읽힌다 — 오인이 규약에 의해 강화되는 구조.

## 옵션과 버린 이유

축: 오인 차단 강도 / 발견가능성 / 보존물의 정직성.

| 옵션 | 결론 | 버린 이유 |
|---|---|---|
| **A. 현상 유지** | 기각 | 매 세션 오인 정정 비용 + drift로 참고 가치가 조용히 소멸 중 + 동시 유지보수 비용까지 계속 냄 |
| **B. HEAD에서 삭제 + git tag `archive/aws-ec2`** | **채택** | HEAD = desired를 정확하게 만드는 유일한 옵션. 오인이 *구조적으로* 불가능(§8 정신). 태그 스냅샷은 "실제로 동작했던 시점"으로 동결되어 오히려 정직한 참고물. 발견 경로는 `git tag -l`로 충분 — CLAUDE.md 포인터 한 줄을 검토했으나 기각(아래) |
| **C. `_archive/` 디렉터리로 이동** | 기각 | 경로가 자기서술적이고 브라우징 발견가능성은 좋으나, HEAD에 남는 한 drift·유지비 문제가 그대로다. **휴면 환경(재구축 계획 실재)일 때만 이기는 옵션** — 사람에게 물었고, 답은 "죽은 환경, 패턴 참고용"이었다 |
| **D. README/마커 파일 추가** | 기각 | 규율 의존 — yaml만 grep하는 agent에게 안 통한다. "규율이 아니라 구조로 강제한다"(§8)와 정면 충돌 |

## 판정 메모

- **CLAUDE.md의 아카이브 포인터("과거 코드는 tag 참조" 한 줄)는 기각했다** — 오인을 끊는 것은 *현행 예시 정리*(aws-ec2 → baremetal)이고, 아카이브의 존재 안내는 별개 문제다. CLAUDE.md는 현행 시스템을 다루는 자리이지 과거의 색인이 아니며, 태그는 `git tag -l`로 자기서술된다. CLAUDE.md 예시 정리만 티켓 범위에 남겼다.

- 전 옵션이 git 위라 되돌리기 비용 한 시간 이하 — **one-way door가 아니므로 ADR 없이**(§4②) 리프 Task로 발행했다. 두 저장소를 저장소별 티켓으로 나누려다 합쳤다 — 티켓의 분할 축은 저장소가 아니라 **검수 단위**이고, 이 일은 의도·태그·검수가 하나다(다중 target-repo 리프, ADR-0016).
- C가 되살아나는 조건을 명시해 둔다: 클라우드 환경 재구축 계획이 실재해지면, 그때는 태그에서 복원해 `_archive/`가 아니라 현행 overlay로 되살리면 된다 — 태그 보존이 그 길도 막지 않는다.
