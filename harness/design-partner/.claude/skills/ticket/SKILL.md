# 티켓 발행

> **잠정판(관측 장비).** 고쳤다면 고친 이유를 마찰 로그에 남긴다.

**close 하는 스크립트가 없다.** 빠뜨린 것이 아니다. PR 머지 ≠ 티켓 종료(§5)이고, 그 사이에 사용자 검수가 산다. **close는 언제나 사람이 한다.** `gh issue close`를 대신 부르지 않는다.

## 1. 타입을 판정한다 — 판단이다

| 타입 | 성격 | 전제 |
|---|---|---|
| **Epic** | 컨테이너 | **공표된 근거 ADR** (superseded·rejected 불가) |
| **Feature** | 컨테이너 (**선택적**) | 없음. ADR은 선택 — 명시하면 같은 게이트를 지난다 |
| **Task** / **Bug** | 리프 | 없음. ADR은 선택(직접 이행 시) — 명시하면 같은 게이트를 지난다 |

**accepted 요구는 발행이 아니라 착수의 문이다.** proposed 근거로도 발행할 수 있다 — 계획의 표현형이 티켓이라, 계획을 펴 보며 결정을 검증할 수 있게 하기 위함이다. 결정이 굳기 전에는 집행 도구(ticket-engineer)의 착수 게이트가 계층 전체의 근거 ADR에 accepted를 요구해 착수를 막는다.

- **Feature는 리프를 묶는 그룹화 컨테이너다.** Epic 밑에서도, Epic 없이 최상위에서도 쓸 수 있다. 근거 ADR을 전제하지 않는다 — 굳은 결정 없이도 여러 Task를 하나의 흐름으로 묶을 수 있다. 명시한 ADR은 게이트를 지난다(답하면 참이어야 한다).
- **조사에는 티켓이 없다**(§5). *계획된* 조사를 백로그에 올릴 때만 `Task`(완료 조건 = discussion 문서 커밋).
- `story`·`spike`는 **없다**.

## 2. 발행한다 — `create.py`

```bash
create.py \
  --type epic|feature|task|bug \
  --title "..." \
  --body-file <path> \
  [--adr ADR-0001]... \              # 반복 가능. Epic 필수 · Feature·리프 선택
  [--target-repo owner/name]... \    # task·bug 는 이것 또는 --no-target-repo 가 필수
  [--no-target-repo] \               # 수정 대상 부재의 명시적 선언 (신규 저장소 생성 등)
  [--ref-repo owner/name]... \       # 참조 저장소 (선택 · 비완전 목록)
  [--blocked-by N]... \              # 선행 티켓. task·bug 는 이것 또는 --no-deps 가 필수
  [--no-deps]                        # 선행 없음의 명시적 선언
```

`gh issue create` + GraphQL `updateIssueIssueType` + Project 등록. `gh issue create`에는 `--type` 플래그가 없다 — Issue Type 지정은 GraphQL로만 된다.

새 티켓은 Project #1에 **타입별 초기 Status**로 들어간다(ADR-0033의 로스터): **Epic·Feature·Task = `Draft`**(확신 전 — 계획·검토 중) · **Bug = `Todo`**(즉각 대처 — "계획중"이 성립하지 않는다). 도구는 초기값만 넣는다 — 이후 전이는 사람의 것이다(§5). **Draft 해제(→ `Todo`)는 "진행되어도 양호한가"의 확신 판정이라 언제나 사람이 한다** — 전이 스크립트는 없다.

### 본문 — `templates/`의 타입별 템플릿에서 시작한다

`epic.md`(Feature도 이것 — 컨테이너 공통) · `task.md` · `bug.md`.

**초안은 `tmp/github-issues/<슬러그>.md` 에 쓴다**(gitignored).

- **공통 절(Summary · Context · Goal · Acceptance Criteria · References)은 이름까지 한 벌이다.** 같은 질문은 같은 자리·같은 이름에서 답한다. 닫는 사람과 집행자가 그 이름을 찾는다. (Bug에는 Goal이 없다 — Expected Behavior가 그 질문에 답한다.)
- **선택 절(Requirements · Technical Notes · Environment · Evidence)은 지우지 않고 부재를 "없음"으로 명시한다.** 빈 절은 누락인지 비해당인지 말하지 못한다.
- **References는 조사에서 얻은 외부 정보 전용이다.** ADR·discussion 등 내부 문서를 넣지 않는다.
- **discussion 링크는 티켓 어디에도 넣지 않는다.** 비구조 문서는 정보 전달에 부적합하다 — 필요한 맥락은 Context로 옮겨 적는다. 근거 ADR이 없는 리프는 Context가 유일한 "왜"다. 충분히 쓴다.
- **'근거 ADR'·'저장소' 절은 템플릿에 없다.** 스크립트가 구조화 절로 박는다(아래). 본문에 손으로 다시 적지 않는다 — 사본은 낡는다.

### 근거 ADR — `--adr`

- **Epic은 공표된 근거 ADR이 필수다**(§5) — 존재의 전제. `--adr` 없이 epic을 만들려 하거나 그 ADR이 `superseded`·`rejected`·미공표면 스크립트가 거부한다(exit 1). **우회하지 않는다** — 죽은 결정·없는 문서로 계획을 펴지 않는다.
- **근거가 여럿이면 `--adr`을 반복한다.** 게이트는 전부에 걸린다 — 하나라도 걸리면 거부.
- **Feature의 근거는 선택이다** — 근거 결정 없이도 리프를 묶을 수 있다(§5).
- **리프의 근거는 선택이다 — 이행 추적의 자리다.** 하위 축 결정을 **직접 이행**할 때만 명시한다(#11이 ADR-0015의 린트를 배선하는 것처럼). 부모 컨테이너의 근거를 되풀이하지 않는다 — 사본은 낡는다. 명시하면 타입 불문 같은 게이트를 지난다: 답하지 않아도 되지만, 답하면 참이어야 한다.
- 굳은 결정을 이행하는 일이 낱개 하나면 그냥 리프로 발행하고 명시한다. Epic은 묶을 낱개가 여럿일 때 세운다 — 빈 컨테이너는 냄새다.
- **스크립트가 두 곳에 박는다**(§1 브리지):
  - 이슈 본문 **'근거 ADR' 절** — YAML 블록(기계용) + HEAD/permalink 링크(사람이 읽고 문서로 건너간다)
  - Project **`ADR` 필드** — 기계가 정확히 필터한다. 컨테이너의 값은 존재 근거(권위), 리프의 값은 이행 추적(비완전 — 명시된 것만 걸린다)
- **문서 쪽에는 되쓰지 않는다.** 동결 문서는 살아 있는 필드를 담지 못한다. 브리지는 이슈가 문서를 가리키는 단방향이다.

### 저장소 맥락 — `--target-repo` · `--no-target-repo` · `--ref-repo` (ADR-0016 파일럿)

- **리프는 저장소 맥락에 답해야 발행된다.** *어디를 고치는가* — `--target-repo`(다수 가능)로 지정하거나, 대상이 아직 없으면(신규 저장소 생성 등) `--no-target-repo`로 부재를 명시적으로 선언한다. 침묵은 스크립트가 거부한다 — 빈 자리는 누락인지 부재인지 말하지 못한다.
- **target은 살아 있는 사실이다.** 작업 중 수정 대상이 늘면 본문 절과 필드를 먼저 갱신한다(필수). 갱신을 시작하는 것은 도구 밖이다(집행자·사람의 규약). 갱신의 실행은 `set-repos.py`(아래).
- **ref는 구조 파악의 출발점이다.** 비완전 — 집행자는 나열 밖도 참조할 수 있다. 갱신은 권장이지 의무가 아니다.
- **컨테이너에는 담지 않는다.** 묶음은 여러 저장소에 걸칠 수 있다 — 집행 맥락은 리프의 것이다.
- **스크립트가 두 곳에 박는다**:
  - 이슈 본문 **'저장소' 절** — YAML 펜스 블록. 사람과 집행 도구가 같은 표기 하나를 읽는다.
  - Project **`Target Repos` 필드** — *"이 저장소를 고치는 열린 리프"* 를 기계가 필터한다.

### 선행 의존 — `--blocked-by` · `--no-deps` (ADR-0017 파일럿)

- **리프는 선행 의존에 답해야 발행된다.** 선행 티켓을 `--blocked-by`(반복 가능)로 걸거나, 없으면 `--no-deps`로 무의존을 명시적으로 선언한다. 침묵은 스크립트가 거부한다.
- **GitHub 네이티브 의존 관계(blocked by)에 건다** — 본문 절·Project 필드는 없다. **사이드바에서 손으로 걸지 않는다** — 갱신은 언제나 `set-deps.py`다(발행과 같은 게이트).
- **선행은 열린 리프만.** 닫힌 이슈·컨테이너는 게이트가 거부한다. 컨테이너 티켓은 의존을 담지 않는다.
- **열린 선행 위의 착수는 집행 도구가 거부한다** — 선행의 완료 기준은 close(사람 검수)다. 작업 중 미기재 선행을 발견하면 `set-deps.py`로 **먼저 갱신한다(필수)**.

### 사후 기입·갱신 — `set-adr.py` · `set-repos.py` · `set-deps.py`

```bash
set-adr.py --issue <N> --adr ADR-NNNN... | --clear

set-repos.py --issue <N> \
  --target-repo owner/name... | --no-target-repo \
  [--ref-repo owner/name]...

set-deps.py --issue <N> --blocked-by <M>... | --no-deps
```

세 스크립트의 공통 규칙:

- 발행과 **같은 게이트**를 지나 **같은 자리**를 다시 쓴다 (`set-adr`·`set-repos`는 본문 절 + Project 필드, `set-deps`는 네이티브 의존 관계).
- **통째로 교체** — 부분 수정이 아니라 전체 답을 다시 낸다. 답의 자리는 언제나 하나다.
- **손으로 고치지 않는다.** 본문 블록은 집행 도구의 파서가 형식 이탈을 거부하고, 의존은 사이드바 손편집이 게이트를 건너뛴다. 갱신은 언제나 스크립트다.

`set-adr.py`:

- `--clear`는 **Epic 외 전용** — Epic의 근거는 존재의 전제라 철회할 수 없다. 근거가 틀렸다면 올바른 전체 목록을 `--adr`로 다시 낸다.

`set-repos.py`:

- **ADR-0016 이전에 발행된 리프**(저장소 절이 없는 티켓)에는 절을 소급 기입한다 — 기존 티켓에 저장소를 연결할 때 이것을 쓴다.
- 구식 산문 절도 YAML 블록으로 교체된다 — 이 스크립트 한 번이 곧 마이그레이션이다.

`set-deps.py`:

- `--blocked-by` 나열이 **선행의 전부**가 된다 — 나열 밖 기존 관계는 제거된다. `--no-deps`는 전부 제거(무의존).

## 3. 계층을 잇는다

```bash
link-sub.py --parent <N> --child <M>
```

GraphQL `addSubIssue`. 스크립트가 거부하는 것은 둘뿐이다(ADR-0010) — **리프는 부모가 될 수 없다 · Epic은 하위가 될 수 없다.** 깊이 상한은 없다(§5) — Feature 밑에 Feature도 온다. **3층을 권장한다** — 얕음은 규칙이 아니라 결과다.

```
근거 ADR ★공표★ ──→ Epic          ← accepted 요구는 착수의 문(집행 도구)
                          ├─ Task            ← 평시: 바로 연결
                          └─ Feature         ← 리프를 더 묶을 때 (ADR 선택)
                                └─ Task

Feature                                      ← Epic 없이 최상위에서도 가능 (ADR 선택)
  ├─ Task
  └─ Feature                                 ← 더 묶을 수 있다 — 필요할 때만. 권장은 3층
        └─ Task
```

## 4. 하지 않는 것

- **close**(§5) — 스크립트가 없다. 사람이 한다.
- **`Closes #N`** 을 PR·커밋에 쓰지 않는다.
- **Status 전이** — 타입별 초기값(`Draft`·`Todo`) 이후는 건드리지 않는다. 사람이 보드에서 옮긴다 — Draft 해제(확신 판정)도, 종착(`Done`·`Cancelled`)도 사람이다. 폐기는 티켓 삭제가 아니라 `Cancelled`다(ADR-0033).
